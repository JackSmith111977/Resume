# Week 0：投递入口与能力基线

> 日期：2026-08-03 ～ 2026-08-07  
> 场景：实习工作日空档  
> 目的：定位真实断点，同时建立简历、岗位池和项目边界，不再等待准备完成后投递。

## 1. 本周必须产出

1. 一份算法六专题诊断表；
2. 一张后端异步任务链路图；
3. 一张最小 Agent Loop 状态图；
4. 一份美团实习事实素材和至少三条候选 bullet；
5. AI 应用全栈版、前端版简历骨架；
6. 首批岗位池与投递记录；
7. Agent 项目的唯一后端栈和六项 MVP；
8. 下一周最多五个 P0。

完成这些产物即为本周达标，不以学习时长判断。

## 2. 周一：算法识别与求职入口

### M：混合识别诊断 1

从一个月内未查看的旧题中随机选择：

- 滑动窗口；
- 二分；
- 单调栈。

每题最多 8 分钟，不写完整代码，只记录：

```text
题目：
候选算法：
题目信号：
暴力方案：
核心状态/不变量：
是否依赖题解记忆：
最终卡点：
```

### M：建立岗位池

收集首批 AI Agent 应用、AI 应用全栈和前端岗位，记录：

- 核心职责；
- 必须要求；
- 加分项；
- 现有匹配证据；
- 主要缺口；
- 使用的简历版本。

### 完成判定

- 三道算法题都有记录；
- 至少五个高或中匹配岗位进入池；
- 能指出一个最高频岗位要求。

## 3. 周二：后端链路与美团事实

### M：画异步解析链路

使用公开抽象场景：

```text
客户端提交文件
→ 创建文档与任务
→ 文件存储
→ 队列/调度
→ Worker 解析
→ 更新状态
→ 前端获取进度
→ 返回结果
```

标出：

- 数据库写入点；
- 事务边界；
- 幂等键；
- 失败点；
- 重试点；
- Trace ID；
- 前端状态来源。

### M：美团事实素材

只写可确认事实：

```text
模块背景：
原有问题：
我的职责：
前端改动：
后端改动：
文件提交与解析如何解耦：
状态如何流转：
失败如何处理：
为什么这样设计：
评审/测试/上线证据：
可公开结果：
保密边界：
```

### 完成判定

- 能回答创建任务成功但消息发送失败、Worker 成功但状态更新超时、用户重复提交三个问题；
- 美团素材没有使用未经验证的指标和绝对结论。

## 4. 周三：算法实现、CS 基础与简历骨架

### L/M：混合识别诊断 2

从树/图、回溯、动态规划各选一道旧题，选择最有把握的一道完整实现。

流程：

1. 前 5 分钟只分析；
2. 写暴力或搜索空间；
3. 写状态和不变量；
4. 再编码；
5. 手动验证边界；
6. 失败时先分类，不直接看完整题解。

### S：共享基础自测

不用资料分别回答：

- 一次 HTTPS 请求发生了什么；
- 进程、线程和异步分别解决什么；
- 索引、事务和 MVCC 各自解决什么。

### M：两版简历骨架

建立：

- AI 应用全栈版；
- 前端版。

只调整定位、经历顺序、技能顺序和候选 bullet，不追求一次完成全部润色。

### 完成判定

- 算法六专题诊断完成；
- 得到识别、状态、实现、验证四项分数；
- 两版简历都能说明为什么这样排序。

## 5. 周四：Agent Loop 与项目范围

### M：画最小 Agent 状态图

不使用框架，设计：

```text
RECEIVED
→ CALLING_MODEL
→ WAITING_TOOL / FINISHED
→ RUNNING_TOOL
→ CALLING_MODEL
```

考虑：

- 格式错误；
- 未知工具；
- 参数非法；
- 工具超时；
- 最大循环次数；
- 用户拒绝敏感操作；
- 进程中断；
- 重复恢复。

### M：锁定项目范围

必须确定：

- 唯一后端主栈；
- 明确用户任务；
- 公开文档集；
- 一个只读 Tool；
- Citation；
- Trace；
- 10～20 条固定评测样例。

写出停止清单：双后端服务、MQ、多 Agent、复杂 MCP、Rerank、长期 Memory、Kubernetes。

### 完成判定

能够指出 Agent Runtime 相比普通循环新增的工程问题，并且项目范围能在两个工作日内完成第一个纵向切片。

## 6. 周五：事实审计、首批投递与 P0

### M：简历对抗性审计

逐条检查：

- 指标是否有测量依据；
- 因果是否成立；
- 个人与团队贡献是否区分；
- 是否存在“根本解决”等绝对结论；
- 是否把密钥管理、XSS、CSRF 等安全概念混淆；
- 是否能回答三层追问；
- 是否触及保密信息。

### M：首批投递

优先投递高匹配岗位，并记录岗位、版本、日期、状态和下一步。

### S：生成最多五个 P0

```text
缺口：
证据：
为什么影响秋招：
下一步最小任务：
验收条件：
```

P0 至少覆盖：

- 一个算法共性问题；
- 一个共享基础或后端问题；
- 一个 Agent 项目问题；
- 一个简历或投递问题。

## 7. 繁忙日降级

当天没有 M/L 空档时只完成一个 S：

- 一道无标签算法分析；
- 一个后端失败场景；
- 一个 Agent 异常分支；
- 一条美团事实或简历审计；
- 一个岗位记录；
- 更新续接点。

不自动把任务挪到周末。

## 8. 本周禁止事项

- 不继续追求新题数量；
- 不看完整 Agent 框架长教程；
- 不开始三服务大项目；
- 不重新系统学习全部前端或 Java；
- 不写长篇无验收知识笔记；
- 不用 AI 替代首轮算法、方案和经历事实判断；
- 不因“还没准备好”暂停投递。
