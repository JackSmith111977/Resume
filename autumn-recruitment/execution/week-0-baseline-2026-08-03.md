# Week 0：工作日能力基线

> 日期：2026-08-03 ～ 2026-08-07  
> 场景：实习工作日空档  
> 本周目的：不急于补课，先定位算法、后端和 Agent 的真实断点。

## 1. 本周必须产出

1. 一份算法六专题诊断表；
2. 一张后端异步任务链路图；
3. 一张最小 Agent Loop 状态图；
4. 一份个人 P0 缺口清单；
5. 下一周任务优先级。

只要形成这些产物，本周即为完成；不以学习时长或题目数量判断。

## 2. 周一：建立基线与算法识别

### M 任务：混合识别诊断 1

从已经做过、一个月内未查看的题目中，随机选择：

- 1 道滑动窗口；
- 1 道二分；
- 1 道单调栈。

每题最多 8 分钟，不写完整代码，只填写：

```text
题目：
候选算法：
题目信号：
暴力方案：
核心状态/不变量：
是否依赖题解记忆：
最终卡点：
```

### S 任务：建立错因标签

只能选择一个主要标签：

- `PATTERN_UNKNOWN`：没见过或不知道模式；
- `RETRIEVAL_FAILED`：学过但没识别；
- `STATE_UNCLEAR`：知道算法但不会定义状态；
- `IMPLEMENTATION_FAILED`：思路正确但写不出；
- `BOUNDARY_FAILED`：边界错误；
- `SOLUTION_MEMORY`：依赖原题解记忆。

### 完成判定

三道题都有记录，并能指出最主要的一个失败类型。

## 3. 周二：后端链路诊断

### M 任务：画异步解析链路

基于公开、抽象场景，不使用保密业务细节，画出：

```text
客户端提交文件
→ 后端创建文档与任务
→ 文件存储
→ 消息/任务队列
→ Worker 解析
→ 更新状态
→ 前端获取进度
→ 返回结果
```

必须在图中标出：

- 数据库写入点；
- 事务边界；
- 幂等键；
- 失败点；
- 重试点；
- Trace ID；
- 前端状态来源。

### S 任务：回答三个问题

1. 创建任务成功但消息发送失败怎么办？
2. Worker 处理成功但状态更新超时怎么办？
3. 用户重复提交同一文件怎么办？

### 完成判定

不是给出标准答案，而是明确哪些问题自己目前无法解释。

## 4. 周三：算法实现与 Agent 概念诊断

### L/M 任务：混合识别诊断 2

从以下主题各随机选择一道旧题：

- 树或图；
- 回溯；
- 动态规划。

选择其中最有把握的一道，用 Python 独立实现。

流程：

1. 前 5 分钟只分析；
2. 写暴力或搜索空间；
3. 写状态和不变量；
4. 再编码；
5. 失败时先分类，不直接看完整题解。

### S 任务：Agent 概念边界

不用资料，各用一句话区分：

- LLM 调用与 Agent；
- Tool Calling 与 MCP；
- RAG 与 Memory；
- Workflow 与 Agent Loop；
- 日志与 Trace；
- Demo 成功与 Evaluation。

### 完成判定

六专题诊断表完成，并得到算法四项分数：识别、状态、实现、验证，各 0～2 分。

## 5. 周四：最小 Agent Loop 诊断

### M 任务：画状态图

不使用框架，设计：

```text
RECEIVED
→ CALLING_MODEL
→ WAITING_TOOL / WAITING_USER / FINISHED
→ RUNNING_TOOL
→ CALLING_MODEL
```

同时考虑：

- 模型输出格式错误；
- 工具不存在；
- 参数不合法；
- 工具超时；
- 最大循环次数；
- 用户拒绝敏感操作；
- 进程中断；
- 重复恢复。

### M/L 可选任务：伪代码

写出最小 Python 伪代码，至少包括：

```python
while not terminal:
    response = call_model(state)
    action = parse(response)
    # validate, execute, persist, trace
```

禁止使用 LangChain / LangGraph；允许使用模型 SDK 的概念接口。

### 完成判定

能够指出 Agent Runtime 与普通循环相比新增的三个工程问题。
