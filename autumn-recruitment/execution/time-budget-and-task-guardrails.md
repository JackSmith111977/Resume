# 时间预算与任务调度强制规则

> 生效日期：2026-08-04  
> 最近修订：2026-08-05  
> 适用范围：秋招准备中的算法、CS、后端、前端、Agent、项目、求职、反馈和归档任务。  
> 目的：防止单一主题无限延伸、提前透支未来任务，同时避免机械计时打断正在形成的认知或工程闭环。

## 1. 本规则解决的问题

2026-08-04 的执行中，当天算法主任务完成后继续推进了未来日期的同领域题目，挤占了岗位调研和 CS / 后端任务。

2026-08-05 的系统课程又暴露了相反的问题：把预算到点机械解释为“立即中断”，会在用户正在复述、推理或完成局部验证时破坏集中，并留下不完整的认知闭环。

因此，本规则同时解决两类失控：

- **范围失控**：当前任务不断开启新问题、新章节和新技术；
- **中断失控**：时间一到就打断当前回答或复述，导致下次重新加载上下文。

所有 Agent 必须把时间、闭环质量和跨流水线进度共同视为任务验收的一部分。

## 2. 每日预算

开始任何当天任务前，先记录可用总时间。默认按以下比例分配：

```text
主任务：最多 60%
不同流水线的最小任务：至少 25%
复测、回填和归档：至少 15%
```

闭环缓冲属于主任务或对应任务的总耗时，不能额外突破当天预算比例。

示例：可用 90 分钟时，推荐主任务 50～55 分钟、跨流水线任务 20～25 分钟、归档 10～15 分钟。主任务的“教学/执行预算 + 闭环缓冲”应包含在 50～55 分钟内。

### 容量档

#### 最低档：不超过 30 分钟

- 一个到期复测，或主任务的 S 版本；
- 保留至少 5 分钟归档；
- 不开启未来日期任务；
- 闭环缓冲通常不超过 5 分钟。

#### 标准档：45～60 分钟

- 一个 M 主任务；
- 一个不同流水线的 S 任务；
- 保留 5～10 分钟归档；
- 闭环缓冲通常为 5～10 分钟，且预先计入主任务总上限。

#### 充足档：75～120 分钟

- 一个 L 主任务；
- 一个不同流水线的 S/M 任务；
- 保留 10～15 分钟复测与归档；
- 单次 L 任务闭环缓冲通常不超过 10 分钟。

## 3. 三级时间边界

每个任务必须区分三个边界，而不是只写一个“硬停止时间”。

### 3.1 计划工作预算 / 软停止

计划工作预算用于主要教学、推导、实现或研究。

预算到点时：

```text
提醒一次软停止已到
→ 禁止开启新概念、新问题、新样例、新章节或新项目切片
→ 进入闭环模式
```

软停止不是要求立刻打断用户当前一句回答，也不是允许继续正常扩展。

### 3.2 闭环缓冲

闭环缓冲只用于完成开始前声明的**当前闭合单元**。

默认上限：

```text
S 任务：最多 5 分钟
M 任务：最多 5～10 分钟
L 任务：最多 10 分钟
```

缓冲必须在 Task Contract 中预留，并计入任务最大时长与当天单领域占比。

### 3.3 绝对停止

出现以下任一条件时绝对停止：

- 闭环缓冲耗尽；
- 当天单领域 60% 上限将被突破；
- 归档时间将被侵占；
- 当前闭合单元已经完成；
- 用户明确要求停止或切换。

绝对停止时，即使闭环仍不完美，也必须保存可审查状态并结束当前任务。

## 4. 什么是闭合单元

闭合单元必须在任务开始前定义，并且明显小于一个章节、完整功能、整套题或路线阶段。

### 教学任务

典型闭合单元：

```text
当前问题的用户回答
→ 必要纠正
→ 一次自己的话复述或局部验证
→ 本节知识卡与未理解点
```

时间到后可以完成这一闭环，但不能借机继续下一个概念、下一组追问或相邻章节。

### 算法与考试

- `/exam A0`：以考试自身时间边界和当前提交为准；到点收卷，不在闭环缓冲中教学；
- `/tutor` 算法：当前推导或当前失败点 → 必要提示 → 一次修正尝试 → 错因记录；
- 不把“做完整道题的所有扩展”默认视为闭环。

### 工程实现

典型闭合单元：

```text
当前原子修改
→ 相关检查或测试
→ 可审查 Diff
→ 风险与下一步
```

不以“整个功能最终上线”作为默认闭环。

### 研究、岗位和简历

典型闭合单元：

```text
当前证据集
→ 当前结论
→ 来源或事实记录
→ 下一步第一动作
```

不因已经打开多个线索而自动完成全部调研。

## 5. 单领域总上限

算法、Agent、后端、前端、求职等任意单一领域，当天最多使用：

```text
当天可用时间的 60%（包含闭环缓冲）
或一个 L 任务的 45～60 分钟总上限（包含闭环缓冲）
```

先到哪个绝对边界，就执行哪个边界。

Agent 无法精确感知现实时间时，必须使用任务边界替代计时：完成当天计划中的一个主任务后，不得直接开启同领域下一项任务，必须先执行调度检查点。

## 6. Task Contract 必填字段

任务进入 `DOING` 前必须填写：

```text
当天可用总时间：
计划工作预算 / 软停止：
预定义闭合单元：
闭环缓冲：
绝对停止时间或最大总时长：
最小可交付版本：
完成判定：
停止判定：
明确不做：
绝对停止后的降级动作：
完成后返回哪个日程 / 总账：
```

### 完成判定与停止判定的区别

- 完成判定：本任务达到什么结果可以提前结束；
- 软停止：停止范围扩张，转入当前闭环；
- 绝对停止：即使未达到理想结果，也必须保存并结束。

算法教学示例：

```text
计划工作预算 / 软停止：35 分钟
预定义闭合单元：当前题的状态、不变量、核心实现和一次测试
闭环缓冲：最多 5 分钟
绝对停止：40 分钟
完成判定：完成当前题教学验收
明确不做：不开始下一题；不扩展第二个底层概念
```

系统课程 S 小节示例：

```text
计划工作预算 / 软停止：15 分钟
预定义闭合单元：当前概念链的一次用户复述、必要纠正和知识卡
闭环缓冲：最多 5 分钟
绝对停止：20 分钟
明确不做：不进入下一章节或相邻机制
```

## 7. 软停止后的执行规则

软停止触发后，执行顺序固定为：

```text
向用户提醒一次
→ 冻结范围
→ 完成当前闭合单元
→ 记录仍未解决的问题
→ 归档
→ 返回总账重新调度
```

软停止后允许：

- 接收并评估当前正在回答的问题；
- 给完成当前闭环所必需的最小纠正；
- 要求一次已经声明过的复述、测试或检查；
- 生成知识卡、Diff 摘要或证据结论。

软停止后禁止：

- 开启新的苏格拉底问题；
- 引入新的概念、机制或反例链；
- 继续下一题、下一章、下一岗位或下一功能；
- 因用户状态良好而恢复正常扩展；
- 多次重复时间提醒，打断当前闭环。

## 8. 绝对停止后的处理

达到绝对停止后，执行顺序固定为：

```text
停止当前交互扩展
→ 保存当前可复测 / 可审查状态
→ 记录未完成部分和准确断点
→ 将剩余任务拆分或降级为 S
→ 保留归档时间
→ 返回总账重新调度
```

禁止：

```text
把“完成当前闭环”扩大解释为做完整个章节
→ 持续加时
→ 接着开启下一项同领域任务
→ 将其他任务全部推迟
→ 整体顺延后续日历
```

未完成任务应拆分、降级、删除或重新排期，不得自动形成无限欠债。

## 9. 任务完成后的强制调度检查点

每完成或停止一个任务，Agent 必须先回答以下问题，不能顺着当前主题直接继续：

```text
1. 计划工作预算和软停止时间是什么？
2. 预定义闭合单元是什么？
3. 软停止是否触发？触发后完成了哪些闭环工作？
4. 是否达到绝对停止？
5. 计划预算和实际投入是否发生偏差？
6. 当前还剩多少可用时间？
7. 今天是否还有不同流水线任务？
8. 下一项是否来自当天日程和 progress-ledger？
9. 下一项是否在提前借用未来同领域任务？
10. 是否仍保留归档时间？
```

检查完成后，才能将下一项移入 `DOING`。

## 10. 禁止提前透支同领域任务

当天不同流水线任务尚未完成时，禁止提前推进未来日期的同领域任务。

例如：

- 当天算法主任务结束后，不能因为状态良好继续做明天的算法题；
- 应先切换到当天的求职、CS、后端、Agent 或归档任务；
- 只有用户在得知时间代价后明确要求，才允许临时覆盖本条规则；
- 覆盖后必须记录被删除或顺延的任务，不能静默牺牲其他流水线；
- 已关闭任务后用户要求继续，应建立新的 Task Contract，而不是无限延长旧任务的闭环缓冲。

## 11. S / M / L 降级规则

每个可选任务应准备最小版本：

### 岗位调研

```text
S：记录 1 个岗位并提取核心要求
M：记录 3 个岗位并合并重复要求
L：记录 5 个岗位，形成学习模块和优先级
```

### 系统链路

```text
S：只建立一个闭合小模型并完成一次复述
M：主链路 + 3 个未知点
L：增加失败、重试、幂等和 Trace
```

### 算法

```text
S：完成到期复测或只做状态推演
M：完成一道题的推导和核心实现
L：完整 ACM 实现、测试、复杂度和复述
```

时间不足时优先降级，不直接取消整个不同领域。

## 12. 新知识和教学的范围护栏

- 每天默认最多开启一个新的主知识单元；
- 一个主任务中最多深入一个非必要底层扩展；
- 新出现但不影响当前验收的问题进入 Backlog；
- 教学状态良好不是继续开启下一题或下一章的理由；
- 当前闭合单元完成后必须回到全局调度，而不是由对话惯性决定下一步；
- “完成章节”不能作为模糊停止条件，必须预先拆成可在缓冲内结束的闭合小节。

## 13. 例外

只有以下情况可以覆盖默认预算：

- 真实笔试或面试正在进行；
- 明确的线上故障或投递截止时间；
- 用户在知晓将牺牲哪些任务后，明确要求继续当前领域。

即使触发例外，也必须：

1. 记录覆盖原因；
2. 指明被取消、降级或替换的任务；
3. 给新的工作声明新的软停止、闭合单元和绝对停止；
4. 保留最小归档；
5. 不自动顺延整份日历。

## 14. Agent 强制执行检查

Agent 在秋招任务中必须遵循：

```text
读取当前日期、日程和总账
→ 确认可用时间
→ 写 Task Contract：软停止 + 闭合单元 + 缓冲 + 绝对停止
→ 执行一个主任务
→ 软停止时冻结范围并完成当前闭环
→ 绝对停止或闭环完成
→ 强制调度检查点
→ 切换不同流水线或降级任务
→ 归档并更新总账
```

如果用户没有提供可用时间，Agent 应基于最低 / 标准 / 充足档做最保守选择；不得因为缺少精确时间而无限扩展。

如果规则发生冲突，默认选择：

```text
更小的预定义闭合单元
> 更少的范围扩张
> 完成当前认知 / 工程闭环
> 保留绝对停止与归档
```

时间规则的核心不是“分钟一到立刻打断”，而是：

> **预算到点关闭范围，缓冲内完成当前闭环，绝对边界到点必须停止。**
