# 时间预算与任务调度强制规则

> 生效日期：2026-08-04  
> 适用范围：秋招准备中的算法、CS、后端、前端、Agent、项目、求职、反馈和归档任务。  
> 目的：防止单一主题无限延伸、提前透支未来任务，并确保多条秋招流水线持续推进。

## 1. 本规则解决的问题

2026-08-04 的执行中，当天算法主任务完成后继续推进了未来日期的同领域题目，挤占了岗位调研和 CS / 后端任务。

根因不是学习速度慢，而是缺少以下约束：

- 开始前没有明确当天总时间；
- 单个领域没有硬上限；
- 任务只有完成判定，没有停止条件；
- 完成任务后没有返回全局日程；
- 剩余时间不足时没有降级到最小交付版本。

因此，所有 Agent 必须把时间和跨流水线进度视为任务验收的一部分。

## 2. 每日预算

开始任何当天任务前，先记录可用总时间。默认按以下比例分配：

```text
主任务：最多 60%
不同流水线的最小任务：至少 25%
复测、回填和归档：至少 15%
```

示例：可用 90 分钟时，推荐主任务 50～55 分钟、跨流水线任务 20～25 分钟、归档 10～15 分钟。

### 容量档

#### 最低档：不超过 30 分钟

- 一个到期复测，或主任务的 S 版本；
- 保留至少 5 分钟归档；
- 不开启未来日期任务。

#### 标准档：45～60 分钟

- 一个 M 主任务；
- 一个不同流水线的 S 任务；
- 保留 5～10 分钟归档。

#### 充足档：75～120 分钟

- 一个 L 主任务；
- 一个不同流水线的 S/M 任务；
- 保留 10～15 分钟复测与归档。

## 3. 单领域硬上限

算法、Agent、后端、前端、求职等任意单一领域，当天最多使用：

```text
当天可用时间的 60%
或一个 L 任务的 45～60 分钟硬停止点
```

先到哪个限制，就执行哪个限制。

Agent 无法精确感知现实时间时，必须使用任务边界替代计时：完成当天计划中的一个主任务后，不得直接开启同领域的下一项任务，必须先执行调度检查点。

## 4. Task Contract 必填字段

任务进入 `DOING` 前必须填写：

```text
当天可用总时间：
本任务预算：
硬停止时间或最大时长：
最小可交付版本：
完成判定：
停止判定：
明确不做：
超时后的降级动作：
完成后返回哪个日程 / 总账：
```

### 完成判定与停止判定的区别

- 完成判定：本任务达到什么结果可以结束；
- 停止判定：即使未达到理想结果，到了什么边界也必须保存进度并结束。

算法示例：

```text
完成判定：完成 P0-01 的推导、ACM 实现、测试和复杂度复述。
停止判定：45 分钟，或完成 P0-01 教学验收。
明确不做：不开始 P0-02；不扩展第二个底层概念。
```

## 5. 任务完成后的强制调度检查点

每完成或停止一个任务，Agent 必须先回答以下问题，不能顺着当前主题直接继续：

```text
1. 当天主任务是否已完成或达到停止点？
2. 计划预算和实际投入是否发生偏差？
3. 当前还剩多少可用时间？
4. 今天是否还有不同流水线任务？
5. 下一项是否来自当天日程和 progress-ledger？
6. 下一项是否在提前借用未来同领域任务？
7. 是否已预留归档时间？
```

检查完成后，才能将下一项移入 `DOING`。

## 6. 禁止提前透支同领域任务

当天不同流水线任务尚未完成时，禁止提前推进未来日期的同领域任务。

例如：

- 当天算法主任务结束后，不能因为状态良好继续做明天的算法题；
- 应先切换到当天的求职、CS、后端、Agent 或归档任务；
- 只有用户在得知时间代价后明确要求，才允许临时覆盖本条规则；
- 覆盖后必须记录被删除或顺延的任务，不能静默牺牲其他流水线。

## 7. 超时处理

主任务达到硬停止点后，执行顺序固定为：

```text
停止扩展
→ 保存当前可复测状态
→ 记录未完成部分
→ 将剩余任务降级到 S 版本
→ 保留归档时间
→ 返回总账重新调度
```

禁止：

```text
为了做完当前主题持续加时
→ 接着开启下一项同领域任务
→ 将其他任务全部推迟
→ 整体顺延后续日历
```

未完成任务应拆分、降级、删除或重新排期，不得自动形成无限欠债。

## 8. S / M / L 降级规则

每个可选任务应准备最小版本：

### 岗位调研

```text
S：记录 1 个岗位并提取核心要求
M：记录 3 个岗位并合并重复要求
L：记录 5 个岗位，形成学习模块和优先级
```

### 系统链路

```text
S：只画主链路
M：主链路 + 3 个未知点
L：增加失败、重试、幂等和 Trace
```

### 算法

```text
S：完成到期复测或只做状态推演
M：完成一道题的推导和核心实现
L：完整 ACM 实现、测试、复杂度和复述
```

时间不足时优先降级，不直接取消整个不同领域。

## 9. 新知识和教学的范围护栏

- 每天默认最多开启一个新的主知识单元；
- 一个主任务中最多深入一个非必要底层扩展；
- 新出现但不影响当前验收的问题进入 Backlog；
- 教学状态良好不是继续开启下一题或下一章的理由；
- 当前任务完成后必须回到全局调度，而不是由对话惯性决定下一步。

## 10. 例外

只有以下情况可以覆盖默认预算：

- 真实笔试或面试正在进行；
- 明确的线上故障或投递截止时间；
- 用户在知晓将牺牲哪些任务后，明确要求继续当前领域。

即使触发例外，也必须：

1. 记录覆盖原因；
2. 指明被取消、降级或替换的任务；
3. 保留最小归档；
4. 不自动顺延整份日历。

## 11. Agent 强制执行检查

Agent 在秋招任务中必须遵循：

```text
读取当前日期、日程和总账
→ 确认可用时间
→ 写 Task Contract 和硬停止点
→ 执行一个主任务
→ 强制调度检查点
→ 切换不同流水线或降级任务
→ 归档并更新总账
```

如果用户没有提供可用时间，Agent 应基于最低 / 标准 / 充足档做最保守选择；不得因为缺少精确时间而无限扩展。

如果规则发生冲突，默认选择更小范围、更早停止和保留跨流水线任务。
