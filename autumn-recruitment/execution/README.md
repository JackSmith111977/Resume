# 工作日碎片化执行系统

> 学习场景：实习工作日中的不固定空档。  
> 原则：不依赖周末，不要求每天出现完整一小时。

## 1. 执行单位

所有任务拆成三种尺寸：

| 类型 | 时间 | 适合任务 |
| --- | ---: | --- |
| S | 10～15 分钟 | 识别、复述、手算、卡片、单个追问 |
| M | 20～30 分钟 | 推导、伪代码、接口/状态设计、小段实现 |
| L | 30～45 分钟 | 完整算法题、可运行切片、模拟面试 |

当天出现什么长度的空档，就从对应队列取任务。不要等待“完整学习时间”。

## 2. 每日最低标准

### 最低完成线

- 1 个 S 型任务；
- 记录下一步。

### 正常完成线

- 1 个 M 型任务；
- 1 个 S 型复盘。

### 充足空档

- 1 个 L 型任务；
- 1 个 S 型总结。

不补时长，只补关键产物。某天实习繁忙时，完成最低线即可。

## 3. 每次开始前

用一分钟回答：

```text
当前主题：
这次只解决什么：
上次停在哪里：
本次完成的判定条件：
```

禁止以“学习 Spring”“复习 Agent”这类无法完成的宽泛任务开工。

## 4. 每次结束前

留下续接点：

```text
本次产物：
仍不理解：
暴露的问题：
下一步第一动作：
相关文件/代码位置：
```

下一步第一动作必须可以直接执行，例如“为 FAILED_RETRYABLE 增加一次合法迁移测试”，而不是“继续研究状态机”。

## 5. AI 使用边界

### 独立区

以下任务首轮不让 AI 生成答案：

- 算法方向判断与实现；
- 核心状态和不变量；
- 项目技术取舍；
- 面试口述。

### 协作区

独立尝试后，AI 可以：

- 提供分级提示；
- 审查代码；
- 设计反例；
- 扮演面试官追问；
- 比较方案；
- 帮助压缩复盘记录。

### 工程区

真实项目可以使用 AI Coding，但必须保留：

- 需求和验收标准；
- 人工方案判断；
- 测试；
- Diff 审查；
- 失败场景验证。

## 6. 固定五日循环

| 日 | 主线 | 典型产物 |
| --- | --- | --- |
| 周一 | 算法识别与错题检索 | 推导卡 |
| 周二 | 后端链路 | API、表、状态机或链路图 |
| 周三 | 算法实现 + Agent 概念 | Python 代码 + 原理卡 |
| 周四 | Agent / 项目纵向切片 | 可运行检查点 |
| 周五 | 混合诊断 + 面试表达 | 周验收与调整 |

固定节奏只用于降低选择成本。遇到连续项目任务时可以延续，但算法至少每周出现三次。

## 7. 进度状态

每个知识节点使用：

```text
TODO
LEARNING
CAN_EXPLAIN
CAN_IMPLEMENT
USED_IN_PROJECT
INTERVIEW_READY
```

只有通过对应验收后才能升级状态。看完资料最多进入 `LEARNING`。

## 8. 每周指标

### 算法

- 无标签识别率；
- 独立推导率；
- 独立实现率；
- 间隔复现率；
- 主要失败原因。

### 后端

- 能独立解释的链路数；
- 完成的 API / 状态机 / SQL；
- 覆盖的失败场景；
- 能做取舍的主题。

### Agent

- 可运行切片数；
- Tool / RAG / Trace / Eval 的完成状态；
- 失败样本数量；
- 任务完成率、延迟和成本记录。

### 求职

- 新增可用简历素材；
- 完成的项目口述；
- 模拟面试暴露的问题。

## 9. 周末规则

周末默认不安排强制任务。

可选用途：

- 休息；
- 补一个因实习完全未完成的关键检查点；
- 做需要本地开发环境的整合；
- 复盘本周，但不依赖周末维持路线。
