# 零基线学习与能力证据规则

> 生效日期：2026-08-04  
> 适用范围：算法、Python、CS 基础、后端、前端、AI Agent、项目与面试表达。

## 1. 默认基线

除非用户在当前训练周期中提供了可复现的独立证据，否则一律按“尚未掌握、需要从零学习”处理。

以下内容都不能单独证明已经掌握：

- 曾经学过、刷过或在项目中接触过；
- 能说出术语或框架名称；
- 看过题解、文档或 AI 生成代码；
- 在提示下完成回答或实现；
- 简历或项目描述中出现过相关关键词。

这条规则不是否定历史经历，而是避免把模糊记忆和术语熟悉度误当成当前可用能力。

## 2. 能力状态

```text
TODO
→ LEARNING
→ REVIEW
→ VERIFIED
```

- `TODO`：尚未开始，或只有未经验证的历史接触；
- `LEARNING`：正在学习，能够在提示下完成部分任务；
- `REVIEW`：已完成教学闭环，等待无提示复测；
- `VERIFIED`：在约束条件下独立完成，并通过延迟复测。

未经独立验证，不得因为用户提到了某个术语而把状态提升为 `LEARNING` 或 `VERIFIED`。

## 3. 教学方式

新知识默认采用以下顺序：

1. 先建立它解决的问题和最小例子；
2. 从直接方案推导瓶颈；
3. 引入机制、状态和不变量；
4. 完成最小实现或可观察实验；
5. 分析失败、边界与相邻概念；
6. 由用户用自己的话复述；
7. 安排 D+1、D+3、D+7 无提示复测。

用户回答“不会”时，应开始教学，而不是继续要求用户证明已有能力。

## 4. 岗位样本的用途

岗位样本首先用于反推学习路线，而不是逼迫用户为每项要求寻找现成证据。

```text
岗位职责与要求
→ 合并同类知识点
→ 标记基础门槛与加分项
→ 建立依赖顺序
→ 生成学习任务
→ 通过项目和复测形成证据
```

在首轮岗位调研中，允许填写：

```text
我的匹配证据：未验证 / 暂无
能力状态：TODO
主要缺口：需要学习
```

只有经过训练、项目实现或面试验证后，才能将岗位要求转化为“我的匹配证据”。

## 5. 执行边界

- 不根据用户偶然说出的术语推断其掌握程度；
- 不跳过基础直接进入框架 API；
- 不把 AI 生成的项目或文档算作用户独立能力；
- 不因零基线而暂停岗位收集和合理投递；
- 岗位高频要求用于调整路线，但不得用单个岗位打乱全部计划。

## 6. 当前应用

`W0-D1-JOB-01` 改为：收集 5 个真实岗位样本，提取岗位要求并反推学习模块、依赖顺序和优先级。

本任务阶段不要求用户提供现成的 Agent、后端或前端能力证据；未验证项统一记录为 `TODO / 待学习`。
