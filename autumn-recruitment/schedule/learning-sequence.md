# 知识依赖与学习顺序

> 用途：确定“先学什么、后学什么、何时允许上升到抽象层”。  
> 原则：先围绕真实问题建立可观察闭环，再解释机制，最后做抽象、取舍和迁移。

## 1. 统一学习单元

每个知识节点都编排成六步：

```text
Anchor：选择一个真实题、Bug、请求或项目场景
→ Observe：手算、运行、画图，观察输入输出和状态变化
→ Implement：实现最小版本
→ Explain：解释机制、状态和不变量
→ Stress：加入边界、失败、并发或条件变化
→ Transfer：迁移到陌生题、系统设计和面试表达
```

完成 Anchor 和 Observe 只代表 D1；能 Explain 才能进入 D2；通过 Stress 才能进入 D3；无辅助 Transfer 才进入 D4。

## 2. 算法学习链

### 阶段 A：语言和具体操作

先解决“知道思路但写不出来”：

- Python 容器、排序、自定义 key；
- `deque`、`heapq`、`bisect`；
- 链表、树、图邻接表模板；
- ACM 输入输出；
- 手动构造边界用例。

证据：从空文件完成基本操作和输入输出，不依赖自动补全。

### 阶段 B：局部模式

按可观察变化学习：

1. 哈希与计数：空间换查找；
2. 双指针：两个位置如何协同移动；
3. 滑动窗口：窗口扩大、收缩和合法条件；
4. 栈与单调结构：尚未解决的元素如何等待；
5. 二分：答案空间和单调性；
6. DFS/BFS：搜索空间和访问状态；
7. 回溯：选择、撤销和剪枝；
8. 堆：动态维护最值；
9. 基础 DP：状态、转移、初值和遍历顺序。

每个模式先从一题手算状态变化，再实现，再抽象题目信号和不变量。

### 阶段 C：混合识别

- 隐藏专题；
- 先写暴力和瓶颈；
- 同时列出两个候选算法；
- 用约束和不变量排除错误候选；
- 对相似题做区别分析。

### 阶段 D：迁移和面试

- 限时混合套题；
- ACM 输入输出；
- 口述从暴力到优化；
- 修改数据范围、返回要求或在线条件；
- 解释正确性与复杂度。

## 3. CS 与后端学习链

### Anchor：一个真实请求

统一锚点：

```text
浏览器上传文件
→ HTTPS
→ Spring Boot API
→ 参数校验和权限
→ 数据库创建任务
→ 异步处理
→ 状态更新
→ 前端查询或订阅结果
```

所有网络、操作系统、数据库和可靠性知识尽量回到这条链路解释。

### D1：组件和具体链路

- URL 到响应的步骤；
- Controller / Service / Repository；
- 表、索引、SQL、事务边界；
- 线程、线程池、任务队列；
- 日志、请求 ID、任务 ID；
- 前端轮询、SSE、WebSocket 的可见行为。

### D2：机制

- DNS、TCP、TLS、HTTP；
- 进程、线程、上下文切换、阻塞和异步；
- B+Tree、联合索引、MVCC、隔离级别；
- Spring Bean、AOP、事务代理；
- Redis 缓存和状态用途；
- MQ 的投递与消费语义。

### D3：失败和可靠性

- 请求超时不等于操作失败；
- 重试和副作用；
- 幂等键、唯一约束、条件更新；
- 消息发送失败、重复消费和积压；
- Worker 成功但状态更新失败；
- Outbox、补偿、取消和人工重试；
- 日志、指标和 Trace 的职责。

### D4：抽象和系统设计

- 同步、异步、轮询、推送的取舍；
- 数据库、Redis、MQ 分别承担什么；
- 单体与服务拆分；
- 容量、延迟、一致性、安全和演进；
- 从前端、全栈和 Agent 视角讲同一系统。

## 4. Agent 学习链

### D1：单次模型调用

- 消息结构；
- 流式与非流式；
- Token、延迟、费用；
- Structured Output；
- 超时和格式错误。

证据：不用 Agent 框架完成一次可测试调用。

### D1～D2：一个只读 Tool

```text
模型提出工具调用
→ 程序校验名称和参数
→ 执行工具
→ 结构化返回
→ 模型继续生成
```

理解模型负责建议、程序负责执行和约束。

### D2：Agent Loop 与状态

- 继续、结束、等待工具、等待用户；
- 最大循环次数；
- 状态持久化；
- Trace；
- 重复恢复和部分成功。

### D2～D3：RAG

从一份公开文档开始：

```text
解析
→ 切分
→ 索引
→ 查询
→ 召回
→ 上下文
→ 回答
→ 引用
```

再讨论 Chunk、Top K、混合检索、Rerank 和版本更新。

### D3：Evaluation、Tracing 与安全

- 固定测试集；
- 工具选择、参数、Recall@K、引用正确性；
- 任务完成率、延迟、费用和失败率；
- Prompt Injection、最小权限和人工确认；
- 失败样本分类和回归。

### D4：Workflow、框架和系统设计

- 确定性 Workflow 与动态 Agent；
- 手写 Loop 与主流框架对比；
- Tool Calling 与 MCP；
- RAG 与 Fine-tuning；
- 单 Agent 与多 Agent；
- 准确性、延迟、费用、安全、恢复的综合取舍。

## 5. 前端学习链

### Anchor：现有项目和 AI 工作台

从具体页面、状态或 Bug 开始，不从框架源码开始。

### D1：语言和页面行为

- HTML 语义、CSS 布局；
- JS 闭包、`this`、Promise、事件循环；
- TypeScript 类型收窄、泛型和运行时校验；
- 手写防抖、节流、并发控制和发布订阅。

### D2：浏览器与框架机制

- 渲染、布局、绘制和合成；
- 缓存、Cookie、Storage；
- React/Vue 更新与状态流；
- SSR、CSR、SSG 的数据边界；
- 构建、模块和代码分割。

### D3：失败、性能和安全

- 首屏慢、无效渲染和主线程长任务；
- XSS、CSRF、CORS；
- 流式输出、取消、断线和刷新恢复；
- 工具确认、引用和 Trace 展示；
- 前端状态与服务端真实状态协调。

### D4：架构与面试

- 组件边界和状态机；
- Context 与外部 Store；
- SSE 与 WebSocket；
- 性能测量和优化顺序；
- 从用户体验、可靠性、安全和可维护性解释方案。

## 6. 求职证据学习链

```text
事实素材
→ 准确 bullet
→ 60 秒故事
→ 3～10 分钟技术深挖
→ 对抗性追问
→ 真实投递和面试反馈
```

### 美团经历

先确认：背景、个人责任、改动、机制、结果和保密边界；再写措辞；最后准备失败、取舍和演进问题。

### Agent 项目

先确保可运行，再写架构；先有测试和失败样本，再声称可靠；先有评测，再声称效果提升。

## 7. 跨领域依赖

```text
Python 基础
→ 算法实现

HTTP + 数据库 + 状态机
→ 异步任务系统
→ Agent 状态持久化和恢复

Structured Output
→ Tool Calling
→ Agent Loop
→ Trace / Eval

文档解析 + 数据库基础
→ RAG
→ Citation / Evaluation

JS 异步 + 状态机
→ 流式 Agent UI
→ 刷新恢复和工具确认

具体项目证据
→ 简历 bullet
→ 项目深挖
→ 系统设计与面试迁移
```

若前置节点未达到 `CAN_EXPLAIN`，后续节点只能做 D1 探索，不应宣称掌握或加入简历核心叙事。
