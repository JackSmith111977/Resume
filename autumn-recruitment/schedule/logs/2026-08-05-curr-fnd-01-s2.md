## 2. AI 教学与纠正

### 客户端与服务端

- 客户端是主动请求能力的程序；
- 服务端是等待并处理请求、提供能力的程序；
- 服务端程序不等于承载它的服务器机器；
- 一台机器可以运行多个服务端进程，同一服务也可以启动多个实例。

### 请求与响应

```text
请求：客户端表达“想做什么”，并携带必要数据
响应：服务端表达“处理结果是什么”，包括成功、失败或返回数据
```

浏览器与后端通常处于不同进程，甚至不同机器。浏览器不能直接调用后端进程里的普通函数或修改其变量，而是发送请求；后端负责身份、权限、参数和状态校验，再决定是否修改自己的状态。

### 通信边界纠正

进程之间并非只能通过 Web 请求通信：

- 同机进程可以使用管道、共享内存等 IPC；
- 浏览器与远程后端通常通过网络请求和响应通信。

本节只建立 Web 场景的请求/响应模型，IPC 细节后置。

### 结果未知与重复副作用

```text
客户端发送创建请求
→ 服务端创建成功
→ 响应在返回途中丢失
→ 客户端只知道“没有收到结果”
```

未收到响应不能证明服务端没有执行。若客户端重试而服务端把每次请求都视为新操作，可能出现重复任务、重复扣款或重复提交。

### requestId / 幂等键

```text
同一次逻辑操作的重试：沿用同一个 requestId
新的逻辑操作：生成新的 requestId
```

服务端可以保存 `requestId → 处理结果`。再次收到同一 `requestId` 时，复用既有结果而不重复执行。

内容哈希不能单独承担这一语义，因为“同一次重试”和“用户主动提交两次相同内容”可能具有相同内容，但属于不同逻辑操作。

幂等的完整实现、并发竞争和存储机制后置到 `BE-05`；本节只保留故障直觉。
