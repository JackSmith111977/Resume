### 1. LLM 调用 vs Agent

状态：D1 有提示 / REVIEW

用户独立回答：

- Agent 有 loop，普通调用是一次性的；
- Agent 会根据上一轮工具结果继续决策；
- 决策上下文包括系统 Prompt、用户 Prompt 和暴露的工具；
- 没有状态就不知道任务进度，可能重复查询天气并产生重复任务。

AI 协助：

- 补充 Agent 不只依据工具结果，还依据用户目标、历史结果和当前状态；
- 区分“上下文”与“状态”；
- 用重复调用、跳步、过期结果和无法停止解释无状态 loop 的风险。

当前边界卡：

> 普通 LLM 调用通常是一次输入到一次输出；Agent 则维护任务状态，并在循环中根据用户目标、历史结果和工具返回决定下一步，直到完成或失败。

### 2. Tool Calling vs MCP

用户独立回答：

- Tool Calling 给模型调用增加结构化参数返回，使应用可以调用工具；

待验证边界：

- Tool Calling 主要描述模型如何表达“要调用哪个工具以及参数是什么”，实际工具通常由宿主应用执行；
- MCP 是客户端与服务端之间发现和访问工具、资源等能力的标准协议，范围不只是一种工具函数参数格式；
