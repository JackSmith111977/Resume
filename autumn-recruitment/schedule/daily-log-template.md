# 每日执行记录模板

> 建议文件名：`logs/YYYY-MM-DD.md`。  
> 一天只记录真正进入 `DOING` 的任务，不复制大量未执行清单。  
> 强制遵循 [`../execution/time-budget-and-task-guardrails.md`](../execution/time-budget-and-task-guardrails.md)。

## 6. 验收

### 通用四门

- [ ] Explain：不看资料讲清楚
- [ ] Predict：预测新输入、异常或边界
- [ ] Modify：改变一个条件仍能处理
- [ ] Test：有测试、反例、演示或模拟证据

### 由具体到抽象

- [ ] 能描述一个具体样例的完整状态变化
- [ ] 能解释关键机制或不变量
- [ ] 能说明至少一个失败模式
- [ ] 能与一个相邻概念或方案比较
- [ ] 能迁移到一个新场景或面试问题

### AI 代码追加

- [ ] 审查完整 Diff
- [ ] 能解释关键数据流和分支
- [ ] 能修改一个小需求
- [ ] 能判断至少一个失败测试
- [ ] 没有擅自扩大范围

### 简历追加

- [ ] 事实由本人确认
- [ ] 团队成果和个人贡献分离
- [ ] 指标有来源或已删除
- [ ] 技术结论准确
- [ ] 能回答对抗性追问

## 7. 软停止与闭环记录

软停止触发时只提醒一次，并冻结范围。此后不得开启新问题或新章节。

```text
软停止实际时间 / 任务边界：
软停止时正在进行的内容：
冻结后的范围：
闭环缓冲内完成：
- 当前回答评估：
- 必要纠正：
- 一次复述 / 测试 / 检查：
- 知识卡 / Diff / 结论：
软停止后是否引入新内容：是 / 否
```

若“软停止后是否引入新内容”为“是”，必须记录原因并标记流程偏差。

## 8. 强制调度检查点

每个任务完成或达到绝对停止后，先填写本节，禁止直接开启下一项同领域任务。

```text
计划工作预算 / 软停止：
预定义闭合单元：
闭环缓冲：
实际投入 / 实际范围：
软停止是否达到：是 / 否
软停止后的闭环工作：
绝对停止是否达到：是 / 否
当前可复测 / 可审查产物：
未完成部分与准确断点：
当前剩余时间：
今天仍未完成的不同流水线任务：
下一任务是否来自今天日程和 progress-ledger：是 / 否
下一任务是否属于未来日期的同领域任务：是 / 否
是否已预留归档时间：是 / 否
```

判断规则：

- 软停止不是立即中断；冻结范围后只完成预定义闭合单元；
- 若“未来日期的同领域任务”为“是”，默认禁止开启；
- 若仍有不同流水线任务，优先执行其 S 版本；
- 若达到绝对停止，立即保存当前状态，不再继续纠错或追问；
- 只有用户在得知代价后明确覆盖，才能继续未来同领域任务；
- 已关闭任务后继续需要新的 Task Contract；
- 覆盖时必须记录被删除、降级或顺延的任务。
