# 周复盘模板

> 建议文件名：`reviews/YYYY-Www.md`。  
> 使用时间：周五或周末。复盘目标不是评价努力程度，而是依据证据调整下一周范围。

## 1. 周信息

```text

本周最多五个 P0：
1.
2.
3.
4.
5.
```

## 3. 深度进展

每个主题只依据无辅助证据填写。

| 主题 | 上周深度 | 当前深度 | 证据 | 下一层缺什么 |
| --- | --- | --- | --- | --- |
|  | D0/D1/D2/D3/D4 |  |  |  |

检查：

- [ ] 没有因为看完资料而升级；
- [ ] 没有因为 AI 生成代码而升级；
- [ ] D2 有机制或不变量解释；
- [ ] D3 有失败、反例或方案比较；
- [ ] D4 有陌生场景、模拟或真实反馈。

## 5. 项目与 Agent

```text
本周可运行纵向切片：
Trace / Tool / RAG / Citation / Eval 状态：
新增测试：
新增失败样本：
修复证据：
用户能独立解释的关键代码：
AI 生成但尚未掌握的代码：
```

范围审查：

- [ ] 仍是一个后端主栈；
- [ ] 仍围绕一个明确任务；
- [ ] 未擅自加入多 Agent、复杂 MCP、MQ、Rerank 或额外服务；
- [ ] 新功能是由测试、用户问题或真实反馈驱动；
- [ ] 新增范围已替换或删除同级任务。

## 6. CS、后端与前端

```text
本周能脱稿解释的链路：
本周完成的接口 / SQL / 状态机 / 排障：
本周覆盖的失败场景：
本周前端独立手写或调试：
仍停留在术语层的内容：
```

由具体到抽象检查：

- [ ] 有真实请求、页面、Bug 或任务作为 Anchor；
- [ ] 能画具体状态和数据流；
- [ ] 能解释网络、OS、数据库或浏览器机制；
- [ ] 能比较相邻方案；
- [ ] 能回答系统设计或项目追问。

## 8. 真实反馈

每个失败事件记录：

```text
事件：
失败层级：知识 / 检索 / 推导 / 实现 / 边界 / 表达 / 证据 / 匹配
证据：
是否重复：
是否命中多个岗位：
是否阻塞项目主链路：
是否升级 P0：
```

冷门单点默认进入 Backlog；重复出现、命中多个岗位或阻塞主链路才升级。

## 9. 人机协作复盘

```text
本周 AI 主要承担：导师 / 考官 / 审查 / 执行 / 归档
AI 提前泄露答案次数：
用户未先独立尝试次数：
AI 生成关键代码但用户未解释次数：
完成的无 AI 复测：
```

需要调整的协作规则：

- [ ] 降低某类任务援助等级；
- [ ] 增加 A0 模拟；
- [ ] 增加 Diff 审查；
- [ ] 删除无学习价值的记录工作；
- [ ] 让 AI 更多承担检索、测试或归档。
