# 秋招学习日程执行系统

> 当前周期：2026-08-04 ～ 2026-09-06  
> 目标：把知识地图转化为每天可开始、可中断、可验收、可记录和可复盘的任务。

## 1. 使用入口

按以下顺序使用：

1. [`learning-sequence.md`](./learning-sequence.md)：确认知识依赖和由浅到深的推进顺序；
2. [`calendar-2026-08-04-to-09-06.md`](./calendar-2026-08-04-to-09-06.md)：查看当天必须完成和可选任务；
3. [`daily-log-template.md`](./daily-log-template.md)：执行一个任务并记录人机协作、证据和复测；
4. [`progress-ledger.md`](./progress-ledger.md)：更新任务、能力、复测和求职状态；
5. [`weekly-review-template.md`](./weekly-review-template.md)：每周五或周末复盘、删除范围并生成下周 P0。

AI 在安排或执行日程前还必须读取上级 [`AGENTS.md`](../AGENTS.md)。

## 2. 编排原则

所有主题遵循同一条学习链：

```text
真实问题 / 具体样例
→ 最小实现或可观察现象
→ 关键机制和不变量
→ 失败模式与相邻概念
→ 抽象模型与方案取舍
→ 新场景迁移与面试表达
```

不按“读完某章”排日程。每天必须产生至少一种可验证证据：

- 独立代码或手算结果；
- 链路图、状态机或数据模型；
- 测试、反例或失败注入；
- 脱稿口述或模拟面试记录；
- 可运行项目切片；
- 可投简历、岗位记录或面试反馈。

## 3. 五层深度

| 层级 | 名称 | 核心问题 | 通过证据 |
| --- | --- | --- | --- |
| D0 | 定位 | 我是否知道自己会不会 | 无辅助诊断、失败标签 |
| D1 | 具体 | 我能否处理一个明确样例 | 手算、代码、链路图、最小接口 |
| D2 | 机制 | 为什么能工作 | 状态、不变量、数据流、运行机制 |
| D3 | 抽象 | 能否比较、组合和处理失败 | 方案取舍、边界、故障恢复、反例 |
| D4 | 迁移 | 能否在陌生题和面试中使用 | 混合题、系统设计、项目防守、真实反馈 |

主题不能因为 AI 给出了完整答案而升级。能力升级必须由用户通过无辅助证据完成。

## 4. 每日容量档位

根据实习空档选择当天档位，不因时间不足放弃整天。

### 最低档：15 分钟

- 完成一个 S 任务；
- 清理当天最紧急的复测；
- 留下下一步第一动作。

### 标准档：45～60 分钟

- 一个 M 主任务；
- 一个 S 复测、算法识别或求职任务；
- 5 分钟归档。

### 充足档：75～100 分钟

- 一个 L 主任务；
- 一个 M 支撑任务；
- 一个 S 求职或复测任务；
- 5～10 分钟归档。

日历中的“必须”按标准档设计；时间不足时先保留主任务和复测，删除可选任务。

## 5. 每日执行循环

```text
读取今日日历
→ 检查 D+1 / D+3 / D+7 复测队列
→ 从必须任务中选择一个主任务
→ 复制 daily-log-template
→ Human First 独立尝试
→ 按 AGENTS.md 允许 AI 介入
→ 验收并记录证据
→ 更新 progress-ledger
→ 写下一步第一动作
```

同一时间最多：

- 一个主编码任务；
- 一个轻量复测或求职任务；
- 一个项目纵向切片。

## 6. 任务标识

日历任务采用：

```text
W{周次}-{日期序号}-{领域}-{序号}
```

领域缩写：

- `ALG`：算法；
- `CS`：网络、操作系统、数据库、Linux；
- `BE`：Java、Spring、后端可靠性；
- `FE`：前端与 AI UI；
- `AG`：AI Agent；
- `PROJ`：Agent 项目；
- `JOB`：简历、投递、面试；
- `REV`：复盘和反馈。

示例：`W1-D3-AG-01`。

## 7. 完成定义

任务只有满足以下条件才能进入 `VERIFIED`：

1. 有仓库位置、代码、图、记录或外部反馈；
2. 用户能解释关键结论；
3. 完成至少一种 Predict / Modify / Test 验收；
4. 已安排或完成 D+1、D+3、D+7 中适用的复测；
5. AI 生成部分和用户独立部分已区分；
6. 没有擅自扩大项目或学习范围。

## 8. 计划调整规则

只在以下情况改动日历主线：

- 真实笔试或面试临近；
- 同类失败重复出现两次以上；
- 项目主链路被阻塞；
- 当周可用时间连续两天显著下降；
- 岗位反馈说明当前定位或简历不匹配。

新增 P0 必须写明替换或删除的旧任务。单个冷门问题只进入 Backlog，不打断主线。
