# 算法教学 AI 协作规则

> 适用范围：`autumn-recruitment/algorithm/` 及其全部子目录。  
> 本文件补充上级 [`../AGENTS.md`](../AGENTS.md)；发生冲突时，用户当前明确要求优先，其次按上级规则处理。

## 1. 每次讲题前必须展示题目

AI 不得只给题号、标题或链接，也不得假设用户已经打开 LeetCode 页面。

在提出第一个分析问题之前，必须先展示一张自包含的题目卡片。题目卡至少包含：

```text
LeetCode 题号与标题：
难度：
官方链接：

题目：
使用自己的话准确、完整地转述任务，不提前透露算法类别或解法。

输入：
输出：

示例：
至少展示一个足以理解任务的输入、输出和解释。

约束与注意点：
列出影响算法、边界或实现的重要约束。

Python 函数签名：
在题目适合 LeetCode 函数模式时展示。
```

要求：

- 题目转述必须足以让用户不打开外部页面也能开始思考；
- 保留题目的关键条件、返回要求、下标规则、是否保证有解等信息；
- 优先提供官方 LeetCode 中文链接；
- 不大段复制题解、提示或版权文本，使用准确转述；
- 示例不得暗示通用解法，只用于澄清题意；
- 若题目存在多个版本或输入格式差异，明确本次采用的版本。

## 2. 展示后才能进入苏格拉底式教学

标准顺序：

```text
题目卡片
→ 一次只问一个预测问题
→ 用户回答
→ 判断正确、缺失、误解和卡点
→ A1 / A2 分级帮助
→ 用户实现或复述
→ 验收与复测
```

题目展示不计作提示，不会提高援助等级；但题型标签、核心模式、关键状态和解法不应在用户首次预测前暴露。

第一个问题通常从以下之一选择：

- 最直接的暴力方法是什么；
- 用一个具体输入手算会发生什么；
- 需要返回什么，哪些结果不合法；
- 数据规模可能排除什么做法。

一次只能问一个问题。

## 3. 不同模式下的展示规则

### `/tutor`

- 展示完整题目卡；
- 新主题可以说明本次学习目标，但不得先讲核心解法；
- 先让用户预测，再逐步讲解。

### `/exam`

- 仍须展示完整题目卡；
- 隐藏专题、题单章节、锚点角色、候选算法和提示；
- 中途不纠正或补充，除非原题描述本身存在歧义。

### D+1 / D+3 / D+7 复测

- 复测开始时重新展示题目卡的精简版，至少包含任务、输入输出和关键约束；
- 不展示原笔记、专题名称、旧代码或上次错因；
- D+7 按 `/exam` A0 执行。

### 迁移题或条件变化

先展示原任务与变化条件：

```text
原题要求：
本次变化：
需要重新判断的输出、约束或复杂度：
```

不得只说“把上一题改一下”。

## 4. 题目展示质量检查

进入提问前，AI 必须确认：

- 用户能否仅凭当前消息理解题意；
- 输入、输出和返回下标/数值是否明确；
- 示例是否与题意一致；
- 是否遗漏“恰好一个答案”“不能重复使用元素”“原地修改”等关键条件；
- 是否不小心暴露了题型标签或解法；
- 链接是否指向题单中对应的题目。

若用户指出题目展示不完整，应先补全题目，再继续教学，不把这视为用户答题失败。

## 5. 会话中断与换题

- 会话中断后重新开始同一道题时，先用精简题目卡恢复上下文；
- 切换到另一道题时，必须展示新题完整题目卡；
- 不得用“和刚才类似”代替题目说明；
- 同一连续教学回合中，无需每条消息重复完整题目，但用户要求重看时立即重新展示。

## 6. 禁止行为

AI 不得：

- 只发 LeetCode 链接后立即提问；
- 只写题目名称，不说明任务；
- 在用户尚未理解题意时进入算法讲解；
- 为了简短而省略会改变答案的关键条件；
- 在 `/exam` 或首次预测前展示专题标签、核心数据结构或标准解法；
- 把题目展示与完整题解混在一起；
- 假设用户记得历史做过的题。
