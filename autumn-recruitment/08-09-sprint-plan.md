# 8 月～9 月初秋招并行冲刺计划

> 版本：v2.0  
> 时间范围：2026-08-03 ～ 2026-09 初  
> 场景：工作日实习碎片时间为主，周末不承担强制补课  
> 目标：边准备、边投递、边建设项目、边根据反馈补洞。

## 1. 四条流水线

每周必须同时产生以下四类产物：

| 流水线 | 周产物 |
| --- | --- |
| 能力 | 算法记录、CS/后端口述或代码 |
| 项目 | 至少一个可运行纵向检查点 |
| 求职 | 简历迭代、岗位池和持续投递 |
| 反馈 | 笔试、面试、项目失败样本及 P0 调整 |

禁止重新回到“全部准备好后再投递”的串行模式。

## 2. 工作日任务尺寸

### S：10～15 分钟

- 无标签判断一道算法题；
- 复述一个网络、OS、数据库或 Agent 概念；
- 审计一条简历 bullet；
- 收集并标注一个岗位；
- 写一个评测样例或项目追问。

### M：20～30 分钟

- 推导一道题并写状态和不变量；
- 实现一个接口、SQL、Tool Schema 或 Trace 字段；
- 画请求链路、状态机或 Agent Loop；
- 完成一次经历素材梳理；
- 复盘一次笔试或面试失败。

### L：30～45 分钟

- 独立完成一道中等题；
- 接通一个项目纵向切片；
- 完成一次 JS/TS 或 Java/Python 手写；
- 进行一次混合模拟面试；
- 完成一版定向简历修改和投递。

## 3. 固定周节奏

| 工作日 | 能力主线 | 项目/求职副线 | 最小产物 |
| --- | --- | --- | --- |
| 周一 | 算法无标签识别 | 岗位池和上周反馈 | 3 道分析 + 5 个岗位 |
| 周二 | CS/后端链路 | 美团/项目简历 | 一张链路图 + 一条可投 bullet |
| 周三 | 算法独立实现 | Agent 原理/框架 | 1 道完整实现 + 1 个最小代码点 |
| 周四 | Agent 项目纵切 | 前端手写维护 | 一个可运行切片 + 一次 JS/TS 手写 |
| 周五 | 模拟/复现 | 投递和周复盘 | 周指标、投递记录和下周 P0 |

有真实笔试或面试时，相关准备替换当日副线，但算法每周至少出现三次。

# Week 0：建立投递入口与真实基线（8/3～8/9）

## 必须完成

### 算法

- 六专题无标签诊断：滑动窗口、二分、树/图、回溯、动态规划、单调栈；
- 至少两道完整 Python 实现；
- 一次 ACM 输入输出练习；
- 记录识别、状态、实现、验证四项断点。

### 后端与 CS

- 画公开抽象的文件异步解析链路；
- 标记事务、幂等、失败、重试、Trace 和前端状态来源；
- 完成网络、OS、数据库各一个 P0 自测。

### Agent

- 不用框架画最小 Agent 状态图；
- 区分 LLM 调用、Tool Calling、Workflow、RAG、MCP、Trace 和 Eval；
- 确定个人项目唯一后端主栈；
- 把 MVP 固定为 Tool + RAG + Citation + Trace + Eval。

### 简历与投递

- 整理美团实习：背景、责任、改动、取舍、结果和保密边界；
- 产出至少 3 条候选 bullet；
- 对现有简历逐条审计指标、因果、个人归因和攻击面；
- 建立 AI 应用全栈版与前端版简历骨架；
- 收集首批岗位并开始投递，不等待 Week 4。

## Week 0 验收

- 一份真实断点清单，最多五个 P0；
- 一版美团经历；
- 两个简历版本骨架；
- 一个已确定范围的 Agent MVP；
- 第一批投递记录。

# Week 1：算法恢复 + CS 基础 + 最小 Agent（8/10～8/16）

## 算法

- 12～15 道无标签分析；
- 6～8 道完整实现；
- 4 道间隔复现；
- 一次 60～90 分钟模拟笔试；
- 两次 ACM 输入输出。

## CS/后端

优先补：

- 一次 HTTPS 请求链路；
- 进程、线程、异步和线程池；
- 索引、事务、MVCC 和条件更新；
- Spring 请求、校验、异常和事务边界。

## Agent 项目

完成：

```text
用户输入
→ 单次模型调用
→ Structured Output
→ 一个只读 Tool
→ 结构化 Trace
```

手写完成后，用一个主流 Agent 框架复刻同一流程并记录它提供、隐藏和限制了什么。

## 求职

- 两版简历进入可投状态；
- 持续投递；
- 完成 60 秒自我介绍和 3 分钟美团经历讲解。

# Week 2：完成项目核心闭环（8/17～8/23）

项目只增加以下能力：

```text
公开文档
→ 解析/切分
→ 检索
→ Agent 判断
→ 一个只读工具
→ 最终回答
→ 真实引用
→ Trace
```

必须补：

- 10～20 条固定测试样例；
- 结构化输出错误；
- 工具不存在或参数非法；
- 模型和工具超时；
- 引用与真实来源的映射。

本周不添加多 Agent、复杂 MCP、MQ、双后端服务、Rerank 或长期 Memory。

算法和投递继续按周指标执行。

# Week 3：工程化和面试化（8/24～8/30）

优先级按顺序：

1. 评测自动化和失败分类；
2. 状态保存和刷新恢复；
3. 流式 UI；
4. Token、费用、延迟和工具失败指标；
5. README、架构图和一键运行；
6. 部署或可复现演示环境。

面试产物：

- 3 分钟项目概述；
- 10 分钟技术深挖；
- Agent、全栈、前端三种叙事；
- 一次算法模拟；
- 一次后端/Agent 系统设计模拟；
- 一次前端项目深挖。

# Week 4：反馈驱动补洞与扩大投递（9 月初）

不再定义为“开始投递周”。本周任务由真实反馈决定：

- 笔试失败：按错因补算法和输入输出；
- 基础追问失败：补对应网络、OS、数据库、JS/Java；
- 项目追问失败：补证据、取舍或失败处理；
- Agent 追问失败：补 Runtime、RAG、Eval、安全或框架比较；
- 投递反馈低：检查岗位匹配、简历定位和经历可信度。

持续扩大投递，并保留前端、AI 应用全栈和 Agent 三个岗位池。

## 4. 每周量化门槛

| 指标 | 最低值 |
| --- | ---: |
| 无标签算法分析 | 12 |
| 独立完整实现 | 6 |
| 7 天间隔复现 | 4 |
| 模拟笔试 | 1 |
| 前端独立手写/调试 | 1 |
| 项目可运行检查点 | 1 |
| 新增岗位样本 | 20～30 |
| 精投 | 10 |
| 其他投递 | 视岗位质量补充 |
| 笔试/面试复盘 | 100% |

第一周诊断可适当降低数量，但必须形成基线。

## 5. 计划失效与降级

- 每日空档持续不足 20 分钟：保留投递、算法识别和一个项目主线，其余降级；
- 两个工作日无法完成项目检查点：立即砍范围，不增加技术；
- 投递量不足：直接从知识学习中划出时间；
- 算法方向正确但代码失败：提高 Python/ACM 手写比重；
- 面试集中出现：停止泛学，按面试反馈突击；
- 周末默认休息，只用于可选整合，不用透支维持错误范围。
