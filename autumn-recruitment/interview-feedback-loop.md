# 笔试与面试反馈闭环

> 目标：把真实失败转化为下一轮最小任务，而不是增加一整套课程。

## 1. 统一分类

每个失败只选择一个主要标签：

- `ALGORITHM_RECOGNITION`：未识别算法方向；
- `ALGORITHM_STATE`：状态、不变量或转移不清；
- `ALGORITHM_IMPLEMENTATION`：代码、边界、输入输出或调试失败；
- `CS_FOUNDATION`：网络、操作系统、数据库、安全；
- `LANGUAGE_OR_FRAMEWORK`：JS/TS、Java、Python、React、Spring 或 Agent 框架；
- `PROJECT_DEPTH`：项目链路、取舍、失败或指标经不起追问；
- `AGENT_RUNTIME`：Tool、Context、RAG、Eval、Trace、安全或恢复；
- `COMMUNICATION`：表达失焦、冗长、没有先给结论；
- `RESUME_MATCH`：定位、关键词或经历顺序不匹配岗位。

## 2. 单次复盘模板

```text
公司与岗位：
阶段：笔试 / 一面 / 二面 / HR
日期：
问题或任务：
我的回答/实现：
结果：
主要失败标签：
直接证据：
正确能力应该是什么：
下一步最小任务：
验收条件：
是否升级为 P0：
```

复盘应在当天或次日完成，避免只剩模糊印象。

## 3. P0 升级规则

满足任一条件可升级：

- 同一问题两次出现；
- 属于主投岗位明确门槛；
- 直接导致淘汰；
- 能在一周内形成可验证改善。

不升级：

- 单个公司的冷门细节；
- 明显偏离当前岗位定位；
- 无法确认是否真的导致失败；
- 需要长期转向模型训练或复杂基础设施。

每周由反馈产生的 P0 不超过三个。

## 4. 最小修复任务示例

### 算法识别失败

不是“重学动态规划”，而是：

- 从混合池选 6 道相邻模式题；
- 每题只写性质、暴力、状态和排除理由；
- 三天后重新无标签识别；
- 验收识别率。

### 项目深度失败

不是“继续完善项目”，而是：

- 补一张特定链路图；
- 为一个失败场景增加测试或 Trace；
- 重录一次 3 分钟回答；
- 让面试官角色继续追问三层。

### 基础知识失败

不是“系统学习网络”，而是：

- 复盘原问题；
- 建立相邻概念对比；
- 连接到当前项目；
- 完成一次脱稿口述和一个排查练习。

### 表达失败

统一使用：

```text
先给结论
→ 说明约束
→ 描述关键机制
→ 给证据
→ 补充取舍和边界
```

## 5. 周度聚合

```text
本周笔试/面试次数：
失败标签分布：
重复出现的问题：
最影响淘汰率的问题：
需要修改的简历表述：
需要增加的项目证据：
下周新增 P0：
下周删除或降级的旧 P0：
```

## 6. 路线调整原则

- 反馈用于缩小范围，不用于无限扩张知识树；
- 多家公司重复出现的问题优先于单一公司的特殊问题；
- 能通过项目、代码和口述共同验证的修复优先；
- 修复完成后必须复测，不能因为“看懂了”就关闭；
- 没有真实反馈时，继续执行既定主线，不频繁追热点。
