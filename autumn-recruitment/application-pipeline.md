# 秋招投递流水线

> 目标：不等待准备完成，通过岗位、笔试和面试反馈持续校准路线。

> 能力判断遵循 [`execution/zero-baseline-learning-policy.md`](./execution/zero-baseline-learning-policy.md)：未经当前轮独立验证的能力一律按 `TODO / 待学习` 处理。岗位样本优先用于反推学习模块，不要求用户先证明已有能力。

## 1. 流程

```text
收集岗位
→ 提取岗位要求
→ 反推学习模块和依赖
→ 判断当前匹配度
→ 选择简历版本
→ 投递
→ 笔试 / 面试
→ 复盘
→ 更新 P0
```

## 2. 岗位池

岗位分为三类：

- A：AI Agent 应用 / AI 应用全栈；
- B：全栈开发；
- C：前端 / AI 前端。

每条岗位记录：

```text
公司：
岗位：
岗位类型：A/B/C
来源：
截止时间：
核心职责：
P0 要求：
加分项：
需要学习的模块：
前置依赖：
学习优先级：
我的匹配证据：未验证 / 暂无 / 已验证证据
主要缺口：
使用简历版本：
状态：
下一步：
```

首轮岗位调研允许直接填写：

```text
我的匹配证据：未验证
能力状态：TODO
主要缺口：需要从零学习
```

不能因为用户说出某个术语，就把它记为匹配证据。

## 3. 岗位样本如何进入学习路线

```text
岗位职责与要求
→ 合并重复知识点
→ 区分基础门槛和岗位加分项
→ 找到前置依赖
→ 排出学习优先级
→ 生成最小任务
→ 用实现、复述和延迟复测形成证据
```

只有满足以下条件之一，岗位要求才升级为当前学习 P0：

- 在多个目标岗位中重复出现；
- 已直接导致笔试或面试失败；
- 属于主投方向的基础门槛；
- 可以在一周内形成可验证改进。

单个冷门要求只进入 Backlog，不立即打乱主线。

## 4. 匹配度

### 高匹配

- 主要职责与现有经历直接对应；
- 至少有两项经过核验的项目或实习证据；
- 缺口可以在短期准备或面试前补齐。

处理：定向修改简历和项目描述，优先精投。

### 中匹配

- 核心方向一致，但存在技术栈或深度差异；
- 可通过共享基础和后续学习证据支撑。

处理：正常投递，记录高频差距，不把未验证能力写成已掌握。

### 低匹配

- 主要要求基础模型训练、复杂算法研究、分布式训练或明显超出当前路线；
- 需要长期重构经历才能匹配。

处理：不因单个低匹配岗位打乱主线。

## 5. 每周指标

| 指标 | 目标 |
| --- | ---: |
| 新增岗位样本 | 20～30 |
| 高匹配精投 | 至少 10 |
| 其他合理投递 | 视岗位质量补充 |
| 笔试/面试复盘 | 100% |
| 因反馈产生的 P0 | 每周最多 3 个 |

数量不是唯一目标，但不能用“还没准备好”长期推迟投递。

## 6. 状态机

```text
DISCOVERED
→ REVIEWED
→ READY_TO_APPLY
→ APPLIED
→ ONLINE_ASSESSMENT
→ INTERVIEWING
→ OFFER / REJECTED / WITHDRAWN
```

每个状态必须有日期和下一步。超过七天没有动作时重新检查岗位是否仍有效。

## 7. 投递前 10 分钟检查

- 岗位类型是否明确；
- 使用了正确简历版本；
- 顶部定位和技能顺序是否匹配；
- 最相关经历是否靠前；
- 是否存在无法证明的指标或技术结论；
- 项目地址和演示是否可访问；
- 是否记录了截止日期和后续状态。
