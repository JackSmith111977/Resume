# 项目、简历与面试闭环

> 目标：把知识转化为招聘方可验证的证据。  
> 原则：一个核心项目覆盖 Agent、全栈和前端三种岗位叙事。

## 1. 求职证据模型

知识只有形成以下证据才计入求职能力：

| 证据 | 说明 |
| --- | --- |
| 独立编码 | 能从空文件完成核心实现 |
| 可运行项目 | 有真实输入、状态、失败处理和部署 |
| 测试与评测 | 能证明功能、质量和 Agent 效果 |
| 设计文档 | 能解释约束、方案和取舍 |
| 面试表达 | 能在没有文档时讲清楚并应对追问 |
| 简历成果 | 用准确、可验证的语言表达贡献 |

## 2. 核心项目定位

建议项目方向：**文档工作流 / 审核 Agent 工作台**。

选择原因：

- 与已有文件解析、异步状态机经验相邻，但可使用公开虚构业务避免保密问题；
- 能自然覆盖上传、解析、RAG、工具调用和长任务；
- 可以展示复杂前端状态；
- 可以展示后端可靠性；
- 可以建立明确评测集，而不是只做聊天机器人。

## 3. 项目最小架构

```text
React / Next.js 或 Vue 前端
├─ 文件与任务工作区
├─ 流式输出
├─ 工具确认
├─ 引用与 Trace
└─ 错误恢复
        ↓
Java Spring Boot 业务后端
├─ 用户/权限
├─ 文档与任务 API
├─ MySQL
├─ 异步任务状态机
├─ 幂等/重试
└─ 日志与指标
        ↓
Python Agent Service
├─ Model Gateway
├─ Context Builder
├─ Agent Loop
├─ Tool Registry
├─ RAG
├─ Trace
└─ Evaluation
```

也可以在时间不足时合并服务，但面试中需要清楚说明拆分依据，而不是为了微服务而拆分。

## 4. MVP 范围

### P0：必须完成

1. 上传公开文档；
2. 创建异步解析任务；
3. 查询任务状态；
4. 文档切分和检索；
5. Agent 调用至少两个只读工具；
6. 流式返回结果；
7. 展示引用来源；
8. 保存执行状态和 Trace；
9. 处理超时、工具失败和重试；
10. 建立固定测试集。

### P1：有时间再做

- 高风险工具的人机确认；
- 任务中断恢复；
- 混合检索和 Rerank；
- 多模型路由；
- 用户长期偏好；
- 管理端评测面板。

### P2：不作为首版目标

- 多 Agent；
- 复杂拖拽工作流；
- 大规模向量数据库；
- Kubernetes；
- 大量第三方工具；
- 过度视觉包装。

## 5. 纵向切片顺序

不要分别完成前端、后端、Agent 后再集成。按纵向能力逐步贯通：

1. 创建任务 → 数据库保存 → 前端展示；
2. 后台执行 → 状态迁移 → 前端轮询；
3. 单次模型调用 → 流式输出；
4. 单工具调用 → Tool Trace；
5. 文档检索 → 引用展示；
6. 失败注入 → 重试和恢复；
7. 测试集 → 自动评测；
8. 部署 → README 和演示。

每个切片都应独立可运行，适合工作日碎片化推进。

## 6. 项目工程要求

### 前端

- 明确任务状态机；
- 处理刷新、断线、取消和重试；
- 增量渲染；
- 可查看工具和引用；
- 错误不能只显示“请求失败”。

### 后端

- API 语义明确；
- 状态迁移受约束；
- 幂等和唯一约束；
- 异步执行与重试；
- 结构化日志和 Trace ID；
- 测试关键失败路径。

### Agent

- Tool Schema 和运行时校验；
- 最大循环次数；
- 上下文预算；
- Trace；
- 评测；
- 权限与敏感操作边界。

## 7. 三种岗位叙事

### AI Agent 应用岗

重点讲：

- 为什么选择 Workflow + Agent 混合；
- Tool Loop、Context、RAG 和评测；
- 如何控制幻觉、成本和循环；
- 工具失败、权限和人工确认；
- Trace 如何推动优化。

### 全栈岗

重点讲：

- API、数据库和异步状态机；
- 幂等、重试、一致性；
- 前后端状态协调；
- 服务拆分与部署；
- 线上问题如何定位和恢复。

### 前端岗

重点讲：

- 长任务与流式 UI；
- 状态模型和组件边界；
- 引用、工具确认和 Trace 的产品设计；
- 性能和错误恢复；
- SSR/CSR 或框架选择。

## 8. 简历表达结构

每条经历优先采用：

```text
业务/技术问题
→ 你的关键动作
→ 采用的机制或方案
→ 可验证结果
```

避免：

- 只列技术名词；
- 把团队结果全部归为个人；
- 使用无法证明的百分比；
- 把 AI 自动生成的代码量当作价值；
- 描述保密业务细节。

### 美团实习素材方向

基于当前已知信息，可继续收集：

- 新项目接手时如何系统梳理架构、流程和逻辑链路；
- 文件提交与解析解耦的原问题和改造目标；
- 异步解析状态机的状态、异常和前端反馈；
- 文档解析识别和快捷意见输入的用户价值；
- 前后端分别承担的模块；
- 方案评审、测试、上线或协作证据。

具体表述需要后续在不违反保密要求的前提下核实。

## 9. 项目深挖问题

每个项目必须准备以下七层：

1. 背景：解决谁的什么问题；
2. 范围：你具体负责什么；
3. 架构：核心组件和数据流；
4. 难点：最难的问题是什么；
5. 取舍：为什么没有选另一个方案；
6. 失败：出现过什么问题，如何定位；
7. 演进：重新设计会怎么改。

额外追问：

- 数据量扩大十倍怎么办；
- 模型不可用怎么办；
- 工具重复执行怎么办；
- 文档中包含恶意指令怎么办；
- 前端刷新后如何恢复任务；
- 如何证明 RAG 或 Agent 确实变好。

## 10. 面试模块

### 算法

- 模式识别；
- 暴力到优化；
- 状态和不变量；
- Python 实现；
- 边界和复杂度。

### 前端

- JS/TS；
- 浏览器；
- React/Next.js 或 Vue；
- 工程化、性能、安全；
- 项目深挖。

### 后端

- Java/Spring；
- MySQL/Redis；
- 事务、并发、异步；
- API 和系统设计；
- 项目可靠性。

### Agent

- LLM 应用基础；
- Tool Calling、RAG、MCP；
- Agent Runtime；
- Evaluation、Trace；
- 安全、成本和失败恢复。

### 行为面试

准备真实案例：

- 快速接手陌生系统；
- 推动一次设计改进；
- 处理模糊需求；
- 发生错误或返工；
- 与导师或同事意见不一致；
- 使用 AI 后如何保证质量。

## 11. 碎片化任务

### S 型

- 回答一个项目追问；
- 改写一条简历 bullet；
- 画一个组件或服务关系；
- 定义一个评测样本。

### M 型

- 完成一个纵向切片设计；
- 写一页技术方案；
- 进行一次项目 3 分钟口述；
- 分析一个失败场景。

### L 型

- 完成一个项目切片；
- 做一次 30 分钟模拟面试；
- 录制并复盘项目讲解；
- 补齐 README、测试或部署。

## 12. 投递前验收

至少具备：

- 一份针对三个岗位分别调整的简历；
- 一个可运行的 Agent 全栈项目；
- 一张清晰架构图和一份技术方案；
- 一组可重复的 Agent 评测；
- 美团实习的完整 STAR / 技术深挖材料；
- 每个主项目 3 分钟版和 10 分钟版讲解；
- 算法、基础知识和系统设计的模拟记录。
