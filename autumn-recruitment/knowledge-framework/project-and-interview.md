# 项目、简历与面试闭环 v2

> 原则：一个小而完整的 Agent 项目覆盖三个岗位叙事；美团实习承担真实业务和 Java 后端证据；不建设技术栈展览馆。

## 1. 求职证据模型

| 证据 | 完成标准 |
| --- | --- |
| 独立编码 | 能从空文件完成核心实现并解释 |
| 可运行项目 | 有真实输入、错误处理和复现方式 |
| 测试与评测 | 能证明功能和 Agent 效果，而非只演示成功案例 |
| 设计与取舍 | 能解释约束、替代方案和停止边界 |
| 实习经历 | 责任、动作、结果和保密边界准确 |
| 面试表达 | 3 分钟和 10 分钟版本均可脱稿回答追问 |
| 市场反馈 | 投递、笔试和面试结果能反哺下一轮 P0 |

## 2. 核心项目定位

建议方向：**公开文档审核 / 问答 Agent 工作台**。

用户闭环：

```text
选择公开文档
→ 提出审核或问答任务
→ 检索相关片段
→ Agent 判断是否调用一个只读工具
→ 返回答案和真实引用
→ 展示 Trace 与关键指标
```

选择原因：

- 与文件解析和异步状态经验相邻；
- 能覆盖前端复杂状态、后端接口、RAG、Tool 和评测；
- 可使用公开数据，不触及实习保密内容；
- 任务成功标准可以被测试，不是泛聊天机器人。

## 3. 首版架构

```text
React / Vue 前端
├─ 文档与任务输入
├─ 流式/最终结果
├─ 引用展示
├─ Tool Trace
└─ 错误与重试
        ↓
单一后端服务
├─ Model Gateway
├─ Context Builder
├─ Agent / Workflow Loop
├─ Tool Registry
├─ RAG
├─ Trace
├─ Evaluation
└─ PostgreSQL / 简单持久化
```

后端主栈只能选择一个：

- Python 适合快速完成 Agent Runtime 和评测；
- TypeScript 适合减少语言切换并结合前端；
- Java 只有在明确需要强化 Java 项目证据时选择。

首版不同时建设 Java 业务服务和 Python Agent 服务。服务拆分作为系统设计题讨论，不作为 MVP 完成条件。

## 4. MVP 六项硬范围

1. 一个明确用户任务；
2. 一个公开文档集和检索；
3. 一个只读 Tool；
4. 回答与真实引用；
5. 结构化 Trace；
6. 10～20 条固定评测样例。

必须覆盖：

- 模型结构化输出错误；
- 工具不存在或参数非法；
- 模型或工具超时；
- 检索不到相关内容；
- 引用无法映射真实来源。

## 5. P1 增量

核心闭环完成后按顺序增加：

1. 状态保存和刷新恢复；
2. 流式 UI；
3. 自动评测与失败分类；
4. Token、费用和延迟；
5. 人工确认；
6. 更稳定的部署和演示环境。

只有评测证明基础检索存在问题时，再增加混合检索或 Rerank。

## 6. 明确停止清单

首版不做：

- 多 Agent；
- 复杂 MCP 远程部署；
- Java + Python 双服务；
- MQ 和分布式任务平台；
- 长期 Memory；
- 多模型路由；
- 大规模向量数据库；
- Kubernetes；
- 拖拽工作流；
- 大量第三方工具；
- 与面试证据无关的视觉包装。

两个工作日无法完成一个纵向检查点时，优先砍功能，不引入新框架。

## 7. 纵向切片顺序

1. 单次模型调用 → 可见输出；
2. 一个只读 Tool → Tool Trace；
3. 文档检索 → 引用展示；
4. 受约束 Loop → 终止、超时和错误；
5. 固定样例 → 自动或半自动评测；
6. 状态保存 → 刷新恢复；
7. README、架构图和演示。

每个切片必须独立可运行、可测试和可讲解。

## 8. 美团实习与个人项目分工

### 美团实习负责证明

- 快速接手陌生系统；
- 需求理解和技术方案；
- Vue / TypeScript / Java 全栈开发；
- 文件提交与解析解耦；
- 异步任务状态机；
- 真实团队协作、评审、测试和交付。

### 个人 Agent 项目负责证明

- 模型调用和 Tool Loop；
- RAG、引用、Trace 和 Evaluation；
- AI 原生前端交互；
- 独立设计、实现、部署和复盘。

不要在个人项目中重复建设一套复杂 Java 微服务，只为填技术名词。

## 9. 三种岗位叙事

### Agent 应用岗

- Workflow 与 Agent 如何划分；
- Tool、Context、RAG 和评测；
- 如何控制幻觉、循环、延迟和费用；
- Trace 如何定位失败并推动改进；
- Prompt Injection 和最小权限。

### AI 应用全栈 / 全栈岗

- API、数据和状态模型；
- 前后端如何协调长任务；
- 错误、超时、重试和刷新恢复；
- 为什么选择单服务，何时拆分；
- 如何测试、部署和定位问题。

### 前端 / AI 前端岗

- 流式与长任务状态；
- 组件边界和状态机；
- 引用、Tool Trace 和错误信息；
- 性能、取消和断线恢复；
- 安全渲染模型输出。

## 10. 简历事实审计

每条 bullet 必须回答：

```text
问题是什么？
我具体做了什么？
使用了什么机制？
结果如何验证？
是个人结果还是团队结果？
指标的基准、环境和测量方式是什么？
面试官最可能攻击哪个因果？
```

删除或重写：

- 无法证明的百分比；
- “从根本上解决”类绝对结论；
- 把配置安全错误归因成 XSS 防护；
- 把 AI 生成代码量描述为价值；
- 把团队成果全部归为个人；
- 只列名词而没有问题和结果。

## 11. 项目深挖七层

1. 背景：解决谁的什么问题；
2. 范围：你具体负责什么；
3. 架构：组件、数据和状态如何流动；
4. 难点：最难的约束是什么；
5. 取舍：为什么没有选择另一个方案；
6. 失败：如何注入、发现、定位和恢复；
7. 演进：数据量、模型或团队变化后如何升级。

必须准备的攻击性追问：

- 模型不可用怎么办；
- 工具重复执行怎么办；
- 文档包含恶意指令怎么办；
- 检索结果与答案不一致怎么办；
- 引用如何保证真实；
- 前端刷新后如何恢复；
- 为什么需要 Agent，而不是固定 Workflow；
- 如何证明改进不是偶然成功；
- 为什么没有用 Java/Python 双服务。

## 12. 投递前验收

- 美团经历已进入简历并可深挖；
- AI 应用全栈版和前端版简历可投；
- Agent 项目可运行，含真实引用、Trace 和固定评测；
- 有架构图、README 和演示步骤；
- 项目有 3 分钟和 10 分钟讲解；
- 每周有算法、基础知识和项目模拟记录；
- 每次真实笔试和面试都有复盘并更新 P0。
