# 后端开发知识路线 v2

> 定位：产品型全栈与 Agent 应用后端，重点是完整业务链路、可靠性和系统表达。  
> 不把目标扩张为传统 Java 后端所有八股和超大规模分布式系统。

## 1. 投递边界

当前后端能力主要服务于：

- AI 应用全栈岗位；
- 前后端完整交付；
- Agent Runtime、工具和业务系统集成；
- 美团实习项目的真实链路表达。

如果未来主投纯 Java 后端，再把 JVM、Spring 源码、MQ 细节、Redis 高可用和大量 Java 八股升级为 P0。当前只保持必要深度。

## 2. Java 基础（P0，目标 L2）

- 基本类型、对象、字符串和不可变性；
- List、Set、Map、Queue；
- 泛型、异常、枚举、注解；
- `equals` / `hashCode`；
- Stream 的适用边界；
- 线程、线程池、Future、CompletableFuture；
- 锁、原子类和并发集合；
- JVM 内存区域、GC 和类加载基础。

独立实现：

- 一个并发上限明确的小型任务；
- 一个 CompletableFuture 聚合；
- 一套合理异常分类和错误返回。

## 3. Spring Boot 请求链路（P0，目标 L2～L3）

- 请求从 Web 容器进入 Controller 的路径；
- Controller、Service、Repository 职责；
- 依赖注入和 Bean 生命周期基础；
- DTO、参数校验和统一异常；
- 配置、环境变量和密钥；
- AOP 的典型用途；
- 事务注解的生效和失效边界；
- 单元测试与集成测试。

验收：完成一个带校验、事务、统一错误、日志和测试的 REST 接口。

## 4. API 与业务建模（P0，目标 L3）

- REST 资源和 HTTP 语义；
- 状态码、幂等、分页、筛选和排序；
- 错误码和可诊断错误；
- Request ID、Trace ID；
- API 版本和兼容性；
- OpenAPI；
- 同步接口、异步任务、回调和流式接口的取舍；
- 资源级权限和合法状态迁移。

需要能设计：

```text
POST /documents
GET /documents/{id}
POST /documents/{id}/parse
GET /tasks/{taskId}
POST /tasks/{taskId}/retry
```

并解释哪些接口需要幂等键、权限和状态约束。

## 5. MySQL 与事务（P0，目标 L2～L3）

- 表、主键、唯一约束和范式边界；
- B+Tree、联合索引和最左匹配；
- 覆盖索引、回表和索引失效；
- `EXPLAIN` 和慢查询；
- ACID、隔离级别和 MVCC；
- 乐观锁、悲观锁和条件更新；
- 长事务和热点行；
- 幂等键、唯一约束和状态机组合防重。

验收：为异步任务表设计索引和状态迁移，解释并发更新如何避免覆盖。

## 6. Redis（P0，目标 L2）

- String、Hash、Set、ZSet 的典型用途；
- Cache Aside；
- 穿透、击穿、雪崩；
- TTL 和淘汰；
- 分布式锁的约束；
- 缓存与数据库一致性的现实取舍；
- Redis 不能替代数据库事务和持久业务事实。

验收：为任务状态查询设计缓存，说明更新、过期、故障和回源行为。

## 7. 异步任务、MQ 与状态机（P0，目标 L3）

必须掌握：

- 为什么异步化：延迟、资源、吞吐和解耦；
- Producer、Broker、Consumer；
- 至少一次、至多一次和所谓“精确一次”的工程含义；
- 重复、乱序、积压和幂等消费；
- 超时、重试、退避和死信；
- 任务取消、人工重试和失败终态；
- 状态机合法迁移；
- 前端轮询、SSE、回调的取舍。

建议状态：

```text
PENDING → QUEUED → RUNNING → SUCCEEDED
                     ├→ FAILED_RETRYABLE → QUEUED
                     ├→ FAILED_FINAL
                     └→ CANCELED
```

验收：设计公开抽象的文件异步解析系统，覆盖重复提交、消息发送失败、消费者宕机、处理成功但状态更新超时和状态查询。

## 8. 一致性、可靠性与并发（P0，目标 L2～L3）

- 请求幂等与业务幂等；
- 唯一约束、幂等键和条件更新；
- 本地事务边界；
- Outbox / 事务消息基础；
- 超时不等于失败；
- 重试必须考虑副作用；
- 限流、熔断和降级；
- 乐观并发控制；
- 可恢复性优先于“永不失败”。

## 9. 认证、权限和安全（P0，目标 L2）

- Session、JWT、Cookie；
- 认证与授权分离；
- RBAC 和资源级权限；
- 密码、Token 和密钥；
- 输入校验、SQL 注入、SSRF 和文件上传；
- Agent 工具最小权限、读写隔离和敏感确认；
- 审计日志。

## 10. 可观测性与部署（P1，目标 L2）

- 结构化日志、指标和 Trace；
- 请求 ID、任务 ID 和 Run ID；
- 错误率、延迟、吞吐和队列积压；
- 健康检查和优雅关闭；
- Docker 镜像、网络、卷和环境变量；
- CI/CD、灰度、回滚和配置基础。

验收：通过日志和 Trace 还原一次异步任务失败链路。

## 11. 系统设计（P1，目标 L2）

统一拆解：

1. 用户和需求；
2. 规模和约束；
3. API；
4. 数据模型；
5. 核心状态和链路；
6. 失败模式；
7. 一致性、安全和权限；
8. 可观测性；
9. 演进和停止边界。

不优先深入复杂共识算法、Service Mesh 和超大规模微服务治理。

## 12. 纯 Java 后端追加项（P1/P2）

只有目标岗位高频要求或面试反馈触发时升级：

- HashMap、ConcurrentHashMap 深入；
- JVM GC、日志和故障排查；
- Spring MVC、Bean、AOP 和事务传播深入；
- MyBatis；
- Redis 持久化、复制和高可用；
- Kafka / RocketMQ 具体语义；
- 常见 Java 八股和更多手写。

不要因为看到单个纯后端 JD，就把整套内容升级为当前 P0。

## 13. 投递前验收

- 能讲清 Spring 请求、事务和数据库索引；
- 独立设计并实现规范 REST 接口；
- 设计异步任务状态机、幂等、重试和失败恢复；
- 比较 Redis、MQ、同步、异步和单服务/拆服务；
- 从一致性、安全、可观测性和恢复解释系统；
- 能用美团实习或公开抽象案例证明上述能力。
