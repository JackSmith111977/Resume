# 后端开发知识路线

> 定位：从“参与过全栈开发”提升到“能独立设计并解释完整业务链路”。  
> 目标：P0 主题达到 L2～L3，能支撑全栈和 Agent 应用岗位。

## 1. Java 基础

### P0（目标 L2）

- 基本类型、对象、字符串与不可变性；
- 集合：List、Set、Map、Queue；
- 泛型、异常、枚举、注解；
- equals/hashCode；
- Stream 的适用边界；
- 线程、线程池、Future/CompletableFuture；
- 锁、原子类、并发集合；
- JVM 内存区域、GC 和类加载基础。

独立实现：

- 一个线程安全的小型任务队列；
- 一个 CompletableFuture 并发聚合；
- 合理的异常分类和错误返回。

## 2. Spring Boot 与请求链路

### P0（目标 L2～L3）

必须掌握：

- 请求从 Web 容器进入 Controller 的路径；
- Controller、Service、Repository 分层职责；
- 依赖注入、Bean 生命周期基础；
- DTO、参数校验、统一异常处理；
- 配置、环境变量和敏感信息；
- AOP 的典型用途；
- 事务注解的生效边界；
- 单元测试与集成测试。

验收：独立完成一个带校验、事务、统一错误和测试的 REST 接口。

## 3. API 与业务建模

### P0（目标 L3）

- REST 资源设计；
- HTTP 方法、状态码与幂等语义；
- 分页、筛选、排序；
- 错误码与可诊断错误信息；
- 请求 ID、Trace ID；
- API 版本和兼容性；
- OpenAPI；
- 同步接口、异步任务接口和回调的取舍。

需要能设计：

```text
POST /documents
GET /documents/{id}
POST /documents/{id}/parse
GET /tasks/{taskId}
POST /tasks/{taskId}/retry
```

并解释哪些接口需要幂等键、权限校验和状态约束。

## 4. MySQL 与事务

### P0（目标 L2～L3）

- 表、主键、外键和范式的实用边界；
- B+Tree 索引、联合索引、最左匹配；
- 覆盖索引、回表、索引失效；
- EXPLAIN 与慢查询定位；
- ACID；
- 隔离级别、脏读、不可重复读、幻读；
- MVCC 基础；
- 乐观锁和悲观锁；
- 长事务和大事务风险。

验收：为异步任务表设计索引，并解释并发更新和状态迁移如何避免覆盖。

## 5. Redis 与缓存

### P0（目标 L2）

- String、Hash、Set、ZSet 的典型用途；
- 缓存旁路模式；
- 缓存穿透、击穿、雪崩；
- TTL、淘汰策略；
- 分布式锁的约束；
- 缓存与数据库一致性的现实取舍；
- Redis 不能替代数据库事务。

验收：为任务状态查询设计缓存方案，并说明更新、过期和失败时的行为。

## 6. 异步任务、消息队列与状态机

### P0（目标 L3，核心差异化）

必须掌握：

- 为什么异步化：延迟、资源、吞吐和解耦；
- Producer、Broker、Consumer；
- 至少一次、至多一次和“精确一次”的工程含义；
- 重复消息、乱序、积压；
- 幂等消费；
- 超时、重试、退避、死信；
- 任务取消和人工重试；
- 状态机的合法迁移；
- 前端轮询、SSE 或回调的取舍。

建议状态：

```text
PENDING → QUEUED → RUNNING → SUCCEEDED
                     ├→ FAILED_RETRYABLE → QUEUED
                     ├→ FAILED_FINAL
                     └→ CANCELED
```

验收：设计“文件提交与异步解析”系统，覆盖重复提交、消费者宕机、超时、重试和状态查询。

## 7. 一致性、可靠性与并发

### P0（目标 L2～L3）

- 业务幂等和请求幂等；
- 唯一约束、幂等键和状态条件更新；
- 本地事务边界；
- 事务消息 / Outbox 基础；
- 超时不能简单等同于失败；
- 重试必须考虑副作用；
- 限流、熔断、降级基础；
- 乐观并发控制；
- 可恢复性优先于“永不失败”。

## 8. 认证、权限与安全

### P0（目标 L2）

- Session、JWT、Cookie 的边界；
- 身份认证与授权分离；
- RBAC 基础；
- 资源级权限；
- 密码和密钥管理；
- 输入校验、SQL 注入、文件上传安全；
- Agent 工具的最小权限和敏感操作确认。

## 9. 可观测性与部署

### P1（目标 L2）

- 结构化日志；
- 指标、日志、Trace 的区别；
- 请求 ID 和任务 ID；
- 错误率、延迟、吞吐和队列积压；
- 健康检查；
- Docker 镜像、网络、卷和环境变量；
- CI/CD 基础；
- 灰度、回滚和配置管理基础。

验收：能通过日志和 Trace 还原一次异步任务失败链路。

## 10. 系统设计基础

### P1（目标 L2）

掌握常见拆解维度：

1. 需求与规模；
2. API；
3. 数据模型；
4. 核心链路；
5. 容量与性能；
6. 失败模式；
7. 一致性与安全；
8. 可观测性；
9. 演进方案。

不优先深入：复杂一致性算法、Service Mesh、超大规模微服务治理。

## 11. 碎片化学习任务

### S 型

- 解释一个索引或事务概念；
- 判断一个接口是否幂等；
- 分析一种任务失败场景；
- 口述一次请求链路。

### M 型

- 设计一个表或接口；
- 画状态机；
- 写 SQL 和 EXPLAIN 分析；
- 为一个任务设计重试和去重。

### L 型

- 实现一个完整接口；
- 实现异步任务纵向切片；
- 做一次文件解析系统设计模拟。

## 12. 后端验收门槛

投递前至少能够：

- 不看资料讲清 Spring 请求、事务和数据库索引；
- 独立设计并实现一个规范 REST 接口；
- 设计异步任务状态机和幂等重试；
- 对 Redis、MQ、同步和异步方案做取舍；
- 从失败恢复、数据一致性、安全和可观测性解释系统。
