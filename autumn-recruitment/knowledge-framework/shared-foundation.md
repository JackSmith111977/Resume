# 共享底座：算法、计算机基础与软件工程

> 版本：v2.0  
> 目标：同时支撑 AI Agent、全栈和前端岗位。  
> 投递前要求：P0 达到 L2，能够解释、实现或排查；P1 达到 L1～L2。

## 0. 统一学习模板

每个主题按以下顺序验收：

```text
解决什么问题
→ 如何工作
→ 为什么这样设计
→ 去掉或用错会怎样
→ 与相邻概念的区别
→ 项目中的应用
→ 面试表达
→ 独立验证
```

只看资料不算完成。

## 1. 算法与独立编码（P0，目标 L2）

### Python 面试语言

必须熟练：

- `list`、`dict`、`set`、`tuple`；
- `deque`、`defaultdict`、`Counter`；
- `heapq`、`bisect`、`sorted(key=...)`；
- 递归、迭代、闭包和常见推导式；
- `ListNode`、`TreeNode`、邻接表和并查集；
- ACM 输入输出、多组测试、边界值和快速调试。

### 高频模式

1. 哈希与计数；
2. 双指针；
3. 滑动窗口；
4. 前缀和与差分；
5. 栈、队列与单调栈；
6. 链表；
7. 二分与二分答案；
8. 树、DFS、BFS；
9. 回溯；
10. 堆与 Top K；
11. 基础动态规划；
12. 图的遍历、拓扑排序和并查集基础。

### 推导能力

每题必须能描述：

```text
题目性质
→ 暴力方案
→ 重复计算或搜索空间
→ 候选优化
→ 状态 / 不变量
→ 正确性依据
→ 复杂度
→ 边界与失效条件
```

### 验收

- 每周 12～15 道无标签分析；
- 每周 6～8 道独立完整实现；
- 每周一次 60～90 分钟混合模拟；
- 每周两次 ACM 输入输出练习；
- 7 天后复现 4～6 道；
- 无标签方向识别率达到 70%；
- 中等题独立通过率逐步达到 50%。

## 2. 计算机网络（P0，目标 L2）

### 必须掌握

- 从 URL 到页面或 API 响应的完整链路；
- DNS 解析与缓存；
- TCP 连接、三次握手、四次挥手、可靠传输和拥塞控制的目的；
- TLS 握手、证书和 HTTPS 信任链；
- HTTP 方法、状态码、Header、Body 和幂等语义；
- HTTP/1.1、HTTP/2、HTTP/3 的核心差异；
- 长连接、连接复用、队头阻塞；
- Cookie、缓存、代理、CDN、CORS；
- SSE、WebSocket、轮询和回调的取舍；
- 超时、重试和网络错误不等于业务失败。

### 相邻概念辨析

- TCP 可靠不等于业务操作只执行一次；
- HTTP 幂等语义不自动提供服务端幂等实现；
- CORS 是浏览器策略，不是服务端授权；
- SSE 适合服务端单向流，WebSocket 适合双向长连接；
- 连接超时、读取超时和业务超时需要分开处理。

### 验收

- 不看资料口述一次 HTTPS 请求；
- 分析一次“前端已超时但服务端可能成功”的处理方案；
- 为 Agent 流式输出比较 SSE、Fetch Stream 和 WebSocket；
- 使用浏览器 Network 或命令行定位一次请求问题。

## 3. 操作系统与并发（P0，目标 L1～L2）

### 必须掌握

- 进程、线程、协程的职责与切换成本；
- 用户态、内核态和系统调用；
- 阻塞、非阻塞、同步、异步的区别；
- CPU 密集和 I/O 密集任务；
- 虚拟内存、栈、堆、页和缺页；
- 锁、条件变量、信号量、原子操作；
- 竞态条件、可见性、原子性和有序性；
- 死锁四条件与规避方法；
- 线程池为什么存在、队列和拒绝策略；
- 文件、Socket、句柄和资源泄漏；
- 进程崩溃、重启和持久化状态的关系。

### 项目连接

- Agent Tool 并发执行如何限制资源；
- 异步文档解析为什么不能只放在线程池里无限排队；
- 进程中断后如何恢复任务；
- Python async、Java 线程池和浏览器事件循环分别解决什么问题。

### 验收

- 解释线程池核心参数和排队风险；
- 写一个有并发上限、超时和取消的最小任务；
- 分析一次死锁或竞态示例；
- 说明 Agent Runtime 为什么需要持久化，而普通内存循环不够。

## 4. 数据库公共基础（P0，目标 L2）

### 数据建模与查询

- 表、行、主键、唯一约束、外键和范式的实用边界；
- B+Tree 索引、联合索引、最左匹配；
- 覆盖索引、回表、选择性和索引失效；
- SQL 执行计划与慢查询定位；
- 分页、排序、聚合和 N+1 问题；
- 数据迁移和向后兼容。

### 事务与并发

- ACID；
- 隔离级别；
- 脏读、不可重复读、幻读；
- MVCC 的目的和快照读；
- 乐观锁、悲观锁和条件更新；
- 长事务、大事务和热点行风险；
- 唯一约束、幂等键和状态机如何共同防重；
- 本地事务不能自动覆盖外部 API 和消息系统。

### 验收

- 为异步任务表设计字段、状态和索引；
- 写出防止重复状态迁移的条件更新；
- 使用 `EXPLAIN` 分析一个查询；
- 解释创建任务成功但消息发送失败的 Outbox 思路。

## 5. Linux 与运行环境（P0，目标 L1～L2）

### 必须掌握

- 文件、目录、权限和环境变量；
- 进程、线程、端口和网络连接；
- 标准输入、输出和错误；
- 日志查看、过滤和管道；
- 磁盘、内存、CPU 和负载；
- 服务启动、退出码、信号和优雅关闭；
- 容器中的进程、网络、卷和环境变量；
- 密钥不得写入仓库或客户端包。

### 常用排查能力

至少会使用或理解：

- `ps`、`top`、`lsof`、`ss`；
- `curl`、`dig`、`ping`、`traceroute`；
- `grep`、`awk`、`sed`、`tail`；
- `df`、`du`、`free`；
- Docker 日志、端口、卷和健康检查。

### 验收

- 定位端口占用；
- 检查服务是否监听和健康；
- 从日志按 Trace ID 还原一次失败；
- 解释容器重启后哪些状态会丢失。

## 6. 软件工程与交付（P0，目标 L2）

### 需求和设计

- 需求目标、范围、约束和验收标准；
- 先建立模块认知，再设计改动；
- 方案突出变化点、失败点和取舍；
- API、数据模型、状态机和异常路径保持一致；
- 设计文档为实现和审查服务，不追求面面俱到。

### 测试

- 单元、集成、端到端和评测的边界；
- 正常路径、边界、失败和恢复；
- 测试替身与真实依赖；
- 回归测试和失败样本分类；
- Agent 评测不能只依赖成功 Demo。

### Git 与协作

- 分支、提交、合并、rebase 和 worktree；
- 小步提交和明确 PR 范围；
- Diff 审查、回滚和冲突处理；
- CI 检查、环境差异和依赖锁定；
- 不把 AI 生成代码视为已验证代码。

### 调试与可观测性

- 先复现，再缩小范围，再提出假设；
- 日志、指标、Trace 的职责；
- 请求 ID、任务 ID、用户操作和版本信息；
- 错误信息必须可诊断；
- 失败注入用于验证恢复设计。

### 验收

- 独立完成一个需求的验收标准、方案、实现、测试和复盘；
- 审查一次 AI 生成 Diff，并指出风险和反例；
- 为一个纵向切片配置最小 CI；
- 用 3 分钟讲清背景、改动、取舍、失败处理和结果。

## 7. 安全公共基础（P0，目标 L1～L2）

- 身份认证与授权；
- 最小权限和资源级权限；
- 输入校验和输出编码；
- XSS、CSRF、SQL 注入、SSRF；
- 文件上传与解析风险；
- 密钥、Token、Cookie 和日志脱敏；
- Prompt Injection 与间接注入；
- 模型输出和工具结果都属于不可信数据；
- 高风险写操作需要固定流程、审计和人工确认。

验收：对 Agent 文档工作台完成一次从浏览器、API、文件、模型到工具的威胁分析。
