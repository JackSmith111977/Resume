# 秋招学习路线 v2

> 目标：九月初前形成可持续投递、可验证项目和可复盘面试的最低竞争闭环。

## 总体阶段

```text
阶段 0：建立投递入口和真实基线
        ↓
阶段 1：恢复算法、独立编码和 CS 基础
        ↓
阶段 2：完成最小 Agent 项目闭环
        ↓
阶段 3：工程化、简历化和面试化
        ↓
阶段 4：由真实反馈持续补洞
```

阶段不是严格串行。投递、简历、算法和项目从阶段 0 起并行。

## 阶段 0：投递入口与诊断

### 目标

用真实证据决定优先级，而不是继续扩充知识清单。

### 必须完成

- 六专题算法无标签诊断；
- 网络、操作系统、数据库各一个 P0 自测；
- 后端异步文件任务链路图；
- 最小 Agent Loop 状态图；
- 美团实习第一版素材和候选 bullet；
- AI 应用全栈版、前端版简历骨架；
- 岗位池和首批投递；
- Agent 项目唯一后端栈与六项 MVP。

### 输出

最多五个 P0 缺口，每个缺口必须附证据、影响、下一步和验收条件。

## 阶段 1：算法、独立编码与共享基础

### 算法 P0

- 哈希、双指针、滑动窗口；
- 栈、队列、链表；
- 二分；
- DFS/BFS、树和图基础；
- 回溯、堆；
- 基础动态规划；
- ACM 输入输出和限时调试。

### 训练方式

```text
无标签抽题
→ 暴力与瓶颈
→ 状态/不变量
→ 独立实现
→ 手动验证
→ 7 天复现
→ 混合模拟
```

### 共享基础 P0

- HTTPS 请求完整链路；
- 进程、线程、异步、线程池；
- 索引、事务、MVCC、条件更新；
- Linux 服务和日志排查；
- 测试、Git、CI、Diff 审查和故障定位。

### 验收

- 无标签识别率逐步达到 70%；
- 中等题独立通过率逐步达到 50%；
- 能解释一个请求、一个并发任务和一个事务状态迁移；
- 每周至少一次前端独立手写或调试。

## 阶段 2：Agent 项目最小闭环

### 项目范围

```text
前端输入
→ 单一后端服务
→ 文档检索
→ 一个只读工具
→ 受约束的 Agent/Workflow
→ 回答与真实引用
→ Trace
→ 固定评测集
```

### Agent P0

- 模型调用、消息、Token 和 Structured Output；
- Tool Schema、校验、权限和错误；
- Agent Loop、终止、超时和最大轮数；
- RAG 的解析、切分、召回、上下文和引用；
- Trace 和 Evaluation；
- Prompt Injection、最小权限和不可信输出。

### 框架最低要求

先手写最小 Loop，再用一个主流框架复刻。必须能解释：

- 框架替你处理了什么；
- 框架隐藏了什么状态和错误；
- 为什么项目采用或不采用它；
- 如何退出框架完成排障。

### 验收

- 可运行、可演示；
- 10～20 条固定样例；
- 至少覆盖格式错误、工具错误、超时和引用错误；
- 能从准确性、延迟、成本、安全和恢复比较方案。

## 阶段 3：工程化与面试化

### 项目工程化顺序

1. 评测自动化和失败分类；
2. 状态保存、刷新恢复和错误处理；
3. 流式 UI；
4. Token、费用、延迟和工具失败指标；
5. README、架构图和一键运行；
6. 部署或稳定演示环境。

### 求职证据

- 美团经历 3 分钟版和 10 分钟版；
- Agent 项目的前端、全栈、Agent 三种叙事；
- 两版定向简历；
- 行为面试案例；
- 算法、基础知识和系统设计模拟记录。

## 阶段 4：反馈驱动补洞

每次真实反馈统一分类：

- `ALGORITHM_RECOGNITION`
- `ALGORITHM_IMPLEMENTATION`
- `CS_FOUNDATION`
- `LANGUAGE_OR_FRAMEWORK`
- `PROJECT_DEPTH`
- `AGENT_RUNTIME`
- `COMMUNICATION`
- `RESUME_MATCH`

只把高频、强相关、会导致淘汰的问题升级为 P0。孤立冷门问题先记录，不立即打乱主线。

## 停止清单

在核心闭环完成前停止：

- 同时建设 Java 和 Python 两套后端；
- 多 Agent；
- 复杂 MCP 部署；
- 大规模向量数据库；
- 困难动态规划和复杂图论；
- Kubernetes、Service Mesh；
- 为完整而完整的长篇笔记；
- 因为“尚未准备好”而暂停投递。

## 每周成功标准

本周必须回答：

1. 新增了什么独立能力？
2. 新增了什么可验证求职证据？
3. 真实投递或项目暴露了什么失败？
4. 哪个旧 P0 应降级或删除？
5. 下周最多五个 P0 是什么？
