# 秋招知识框架总览

> 适用岗位：AI Agent 应用开发、全栈开发、前端开发  
> 当前主线：AI Agent 应用开发  
> 基准日期：2026-08-03

## 1. 掌握等级

统一使用四级标准，避免“看过”被误判为“掌握”。

| 等级 | 定义 | 验收方式 |
| --- | --- | --- |
| L1 能解释 | 知道概念、用途、边界和相邻概念 | 不看资料讲清楚，并回答基础追问 |
| L2 能实现 | 能从空文件写出最小版本 | 独立编码、测试、复杂度或错误处理 |
| L3 能工程化 | 能在项目中使用并处理失败 | 日志、测试、性能、异常、权限、部署 |
| L4 能设计取舍 | 能比较方案并完成系统设计 | 给出约束、方案、权衡、演进路径 |

秋招目标：

- 共享底座：核心主题达到 L2；
- 前端：已有优势主题达到 L3；
- 后端：核心业务链路达到 L2～L3；
- Agent：核心运行机制达到 L3；
- 高级分布式、模型训练等非主线主题保持 L1。

## 4. 优先级标记

每个主题使用三种优先级：

- **P0**：九月投递前必须掌握；
- **P1**：投递后持续补强，进入高频面试前完成；
- **P2**：按岗位和面试反馈选择性深入。

## 5. 学习闭环

每个主题必须经过：

```text
知识定位
→ 最小概念
→ 相邻概念辨析
→ 独立实现
→ 项目应用
→ 面试表达
→ 间隔复测
```

单纯阅读文档、观看课程或让 AI 生成代码不计为完成。

## 6. 框架与协议的使用原则

- 先手写最小模型调用、工具分派和状态循环，再使用 Agent SDK；
- 先理解确定性 Workflow 与动态 Agent 的区别，再进入 LangGraph；
- 先理解 Tool Calling，再学习 MCP 的客户端、服务器和传输层；
- 先建立测试集和指标，再谈 Agent 优化；
- 多 Agent 属于 P2，除非单 Agent 已经出现明确职责隔离需求。

## 7. 动态核验

以下内容会快速变化，学习或投递前需要重新核验：

- 模型 API、工具调用和结构化输出接口；
- OpenAI Agents SDK、LangGraph 等框架的当前抽象；
- MCP 规范、SDK 与传输方式；
- React、Next.js、Vue、Spring Boot 的主版本与推荐实践；
- 目标公司的岗位名称、技术栈和面试流程。

框架版本不是学习目标，稳定的核心问题才是：状态、工具、上下文、可靠性、评测、权限和成本。
