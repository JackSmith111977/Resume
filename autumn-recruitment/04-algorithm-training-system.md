# 算法训练体系 v2

## 1. 当前问题

已完成约 200 道题，主要按专题学习。当前主要风险不是题量不足，而是：

- 专题内能理解，混合场景识别困难；
- 知道算法名称，但不会重新定义状态和不变量；
- 间隔后依赖原题解记忆；
- 思路正确时，Python 实现、ACM 输入输出或边界验证仍可能失败；
- 缺少限时混合模拟，无法估计真实笔试表现。

## 2. 训练目标

从：

> 记住这道题怎么写

转变为：

> 根据题目性质重新生成方案，并在限时、无标签条件下完成实现和验证。

## 3. 单题闭环

```text
题目信号：
约束与数据规模：
暴力方案：
暴力瓶颈：
候选优化：
核心状态：
核心不变量：
正确性依据：
复杂度：
边界用例：
算法失效条件：
最终错因：
复现日期：
```

首轮 10 分钟内禁止查看题型标签和完整题解。

## 4. 提示等级

1. 只指出题目中的关键性质；
2. 给出算法类别；
3. 提示状态；
4. 提示不变量或转移；
5. 给伪代码；
6. 最后才看完整代码。

记录自己使用了哪一级提示。需要 4 级及以上提示的题，不计为独立完成。

## 5. 错因标签

每题只能选择一个主要错因：

- `PATTERN_UNKNOWN`：不知道相关模式；
- `RETRIEVAL_FAILED`：学过但未识别；
- `STATE_UNCLEAR`：知道方向但状态或不变量不清；
- `IMPLEMENTATION_FAILED`：思路正确但代码失败；
- `BOUNDARY_FAILED`：边界或验证失败；
- `COMPLEXITY_FAILED`：复杂度不满足；
- `SOLUTION_MEMORY`：主要依赖原题解记忆；
- `IO_OR_DEBUG_FAILED`：ACM 输入输出或调试失败。

周复盘只针对最高频错因设计下一周任务。

## 6. 每周训练结构

| 类型 | 最低数量 | 目的 |
| --- | ---: | --- |
| 无标签快速分析 | 12～15 | 训练模式识别和候选生成 |
| 完整独立实现 | 6～8 | 训练代码、验证和复杂度 |
| 7 天间隔复现 | 4～6 | 检查是否脱离题解记忆 |
| ACM 输入输出 | 2 | 适配真实笔试环境 |
| 60～90 分钟混合模拟 | 1 | 检查时间分配和稳定性 |

Week 0 作为基线周可以减量，但必须完成六专题诊断。

## 7. 间隔复现

每道进入 Review 的题按以下周期复现：

```text
D+1：只复述性质、状态和不变量
D+3：写伪代码或核心转移
D+7：完整独立实现
D+14：混入无标签题池
```

复现时不得看原笔记标题、专题和代码。连续两次独立通过后才可降频。

## 8. 模拟笔试

每周一次：

- 60～90 分钟；
- 2～3 道混合题；
- 使用真实输入输出格式；
- 不用 AI，不看标签；
- 记录每题分析、编码、调试时间；
- 结束后先分类错因，再看题解。

模拟后必须回答：

1. 是否选错题或时间分配失衡；
2. 是识别、状态、实现还是验证失败；
3. 哪类问题在真实笔试中最可能淘汰；
4. 下一次只改进一个什么行为。

## 9. 结果指标

不以刷题数作为主要指标，记录：

- 无标签方向识别率；
- 独立推导率；
- 独立实现通过率；
- 7 天间隔复现率；
- 平均首次正确时间；
- ACM 输入输出失败次数；
- 主要错因分布。

九月前阶段目标：

- 5 分钟内提出合理方向和核心状态；
- 无标签方向识别率达到 70%；
- 基础到中等题独立通过率逐步达到 50%；
- 能在 20～30 分钟完成高频简单/中等题；
- 能清楚口述暴力到优化的推导过程。

## 10. AI 使用边界

首轮独立区：

- 题型判断；
- 暴力方案；
- 状态和不变量；
- 编码和手动验证。

独立尝试后 AI 可以：

- 按提示等级提供最小提示；
- 生成反例；
- 审查复杂度和边界；
- 对比两种方案；
- 模拟面试官追问。

AI 生成的完整答案不能计入独立通过。

## 11. Python 定位

Python 是算法和现场通用编码主语言。必须熟练常用容器、堆、二分、排序、递归、图结构和 ACM 输入输出。

TypeScript 与 Java 不用于日常刷题主线，但每周保留岗位专项手写，防止只会 Python 而无法应对项目代码追问。
