# 秋招总体战略与岗位定位

> 版本：v2.0  
> 基准日期：2026-08-03  
> 目标：用共享工程主干支撑 AI Agent 应用、AI 应用全栈和前端岗位，并通过真实投递反馈持续校准。

## 1. 岗位定位

### 第一优先级：AI Agent 应用 / AI 应用全栈

目标不是基础模型训练、强化学习研究或 AI Infra，而是把模型能力接入真实业务，完成可用、可靠、可评测的产品闭环：

- LLM API、Structured Output、Tool Calling；
- Context、RAG、状态和 Workflow；
- Agent Loop、Trace、Evaluation；
- 权限、安全、成本、超时和恢复；
- 前端交互、后端服务、数据与部署。

### 第二优先级：全栈开发

定位为“前端优势 + 后端业务链路 + AI 应用能力”的产品型全栈，不把目标扩张为传统 Java 后端全知识树。

需要能够独立负责：

```text
需求理解
→ 技术方案
→ 前端交互
→ 后端接口与数据
→ 异步任务和失败恢复
→ 测试部署
→ 线上观测
```

### 第三优先级：前端开发 / AI 前端

利用已有 React、Next.js、Vue、TypeScript 和复杂交互经验，重点恢复独立手写与调试，并突出：

- JavaScript / TypeScript 深度；
- 浏览器、网络、性能和安全；
- 复杂状态与工程质量；
- 流式输出、长任务、工具确认、引用与 Trace 等 AI 原生交互。

## 2. 四条并行流水线

旧模式“准备完成后再投递”停止执行，改为：

```text
A. 能力补强：算法、CS 基础、后端和 Agent
B. 项目证据：一个收缩后的 Agent 纵向切片
C. 求职证据：美团经历、双版本简历和项目讲解
D. 市场反馈：岗位池、投递、笔试、面试和复盘
```

四条流水线每周都必须有产出。任何一条连续两周没有产出，都视为路线失衡。

## 3. 统一能力模型

```text
算法与计算机基础
        ├─ 前端交互与体验
        ├─ 后端业务与可靠性
        ├─ Agent 工程化
        └─ 软件工程与交付
                  ↓
        简历、项目和面试证据
```

| 能力层 | 前端岗位 | 全栈岗位 | Agent 应用岗位 |
| --- | --- | --- | --- |
| 算法与编码 | 面试门槛 | 面试门槛 | 面试门槛 |
| CS 基础 | 网络/浏览器重点 | 网络/OS/DB 重点 | 系统可靠性底座 |
| 前端 | 核心 | 重要 | 产品交互层 |
| 后端 | 协作理解 | 核心 | Runtime 与业务集成底座 |
| Agent | 加分 | 差异化方向 | 核心 |
| 软件工程 | 核心 | 核心 | 核心 |

## 4. 技术栈职责

- **Python**：算法、现场通用编码、Agent 后端原型、评测脚本；
- **TypeScript + React/Vue**：前端、Agent UI、Node 集成；
- **Java + Spring Boot**：美团经历、后端纵向切片、事务与系统设计表达；
- **SQL**：数据建模、查询、索引和事务；
- **Docker / Linux / GitHub Actions**：交付、诊断和验证。

项目首版只选择一个后端主栈。除非单服务已完成并出现明确拆分需求，否则不同时建设 Java 业务服务和 Python Agent 服务。

## 5. 当前时间权重

Week 0 诊断前：

| 方向 | 权重 | 验收 |
| --- | ---: | --- |
| 算法与独立编码 | 35% | 无标签识别、完整实现、间隔复现、模拟笔试 |
| Agent 项目与原理 | 25% | Tool + RAG + Trace + Eval 最小闭环 |
| 后端与 CS 基础 | 20% | 网络、OS、DB、请求链路和可靠性可解释 |
| 简历、投递与面试 | 10% | 美团 bullet、双版本简历、岗位池和反馈记录 |
| 前端维护 | 10% | JS/TS 手写、状态建模、Bug 定位和项目深挖 |

调整规则：

- 算法连续两周无标签独立通过率低于 40%，提高算法权重；
- 没有可演示项目切片，优先砍功能而不是继续补概念；
- 有笔试或面试安排时，相关反馈项立即进入 P0；
- 前端手写或项目追问出现明显退化，前端权重不得低于 10%；
- 投递量不足时，不允许以“还没准备好”为理由推迟。

## 6. 项目范围

首版必须：

1. 一个明确用户任务；
2. 一次文档检索并返回真实引用；
3. 一个只读 Tool；
4. 一个受约束的 Agent / Workflow Loop；
5. Trace；
6. 10～20 条固定评测样例；
7. 可运行和可演示。

首版暂缓：

- Java + Python 双服务；
- MQ 和复杂分布式任务；
- 多 Agent；
- 复杂 MCP 远程部署；
- Rerank、多模型路由、长期 Memory；
- Kubernetes、Service Mesh 和拖拽工作流。

## 7. 学习原则

1. **反馈优先**：真实 JD、笔试和面试反馈高于静态课程表；
2. **门槛优先**：先修复算法、独立编码、简历缺口等淘汰风险；
3. **最小闭环优先**：先完成可运行纵向切片，再扩展功能；
4. **原理后接框架**：手写最小 Loop 后，用一个主流框架复刻并比较；
5. **证据驱动**：每个主题必须产生代码、测试、设计、口述或投递反馈；
6. **事实审计**：简历中每个指标、因果和个人贡献都必须可解释；
7. **AI 放大而非替代**：首轮推导、核心取舍和面试表达必须独立完成。

## 8. 最终求职证据

- **算法证据**：识别率、独立通过率、间隔复现率和模拟笔试；
- **项目证据**：可运行 Agent MVP、Trace、评测、错误处理和部署说明；
- **实习证据**：美团项目的背景、责任、方案、取舍、失败和结果；
- **基础证据**：网络、操作系统、数据库、前后端和 Agent 的独立口述；
- **投递证据**：岗位池、版本匹配、笔试/面试结果和路线调整记录。
