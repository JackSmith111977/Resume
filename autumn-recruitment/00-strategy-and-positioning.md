# 秋招总体战略与岗位定位

> 版本：v1.0  
> 基准日期：2026-08-03  
> 目标：用一套共享能力主干，同时支撑 AI Agent 应用开发、全栈开发和前端开发岗位。

## 1. 岗位定位

### 第一优先级：AI Agent 应用 / AI 应用全栈开发

目标不是基础模型训练、强化学习研究或 AI Infra，而是把大模型能力接入真实业务系统，完成可用、可靠、可评测的产品闭环。

典型工作包括：

- LLM API 与模型路由；
- Structured Output 与 Tool Calling；
- RAG、Context、Memory；
- Agent Loop、Workflow、状态持久化；
- MCP 与外部系统集成；
- Trace、Evaluation、权限、安全和成本控制；
- 前端交互、后端服务和生产部署。

### 第二优先级：全栈开发

全栈不是“前后端都知道一点”，而是能够独立负责：

```text
需求理解
→ 技术方案
→ 前端交互
→ 后端接口
→ 数据存储
→ 异步任务
→ 测试部署
→ 线上观测
```

它既是独立投递方向，也是 Agent 应用开发的工程底座。

### 第三优先级：前端开发

利用已有前端积累保持竞争力，重点突出：

- JavaScript / TypeScript 深度；
- 浏览器与网络原理；
- Vue / React 工程能力；
- 复杂状态与性能优化；
- AI 原生交互：流式输出、长任务状态、工具确认、可追溯结果。

## 2. 路线选择依据

当前招聘市场同时存在两类 Agent 岗位：

1. **模型与研究路线**：模型训练、强化学习、Agentic Model、AI Infra、论文与数学要求较高；
2. **应用与工程路线**：大模型应用、AI Coding、业务系统、工具集成、全栈交付与评测。

结合现有经历和可用准备时间，选择第二类作为主线。该路线能最大化利用：

- 前端与全栈项目经验；
- 美团真实业务系统经历；
- AI Coding、文档驱动和上下文工程经验；
- 对异步解析、状态机和系统梳理的实践。

## 3. 统一能力模型

```text
                  ┌─ 前端交互与体验
算法与计算机基础 ─┼─ 后端业务与可靠性 ── Agent 工程化
                  └─ 软件工程与交付
```

三个岗位不是三条平行路线，而是共用底座后形成不同强调：

| 能力层 | 前端岗位 | 全栈岗位 | Agent 应用岗位 |
| --- | --- | --- | --- |
| 算法与编码 | 面试门槛 | 面试门槛 | 面试门槛与任务编排基础 |
| 前端 | 核心 | 重要 | AI 产品交互层 |
| 后端 | 了解协作 | 核心 | Agent 运行与业务集成底座 |
| Agent | 加分 | 加分/业务方向 | 核心 |
| 软件工程 | 核心 | 核心 | 核心 |

## 4. 技术栈分工

为避免多语言互相干扰，固定语言职责：

- **Python**：算法题、现场通用编码、Agent 原型与评测脚本；
- **TypeScript + Vue/React**：前端、Agent UI、Node.js 集成；
- **Java + Spring Boot**：后端业务、事务、异步任务与系统设计表达；
- **SQL**：数据建模、查询优化和事务；
- **Docker / Linux / GitHub Actions**：交付和验证。

不要求三个语言都用于刷算法；算法统一使用 Python，岗位专项手写再分别补 TypeScript 与 Java。

## 5. 当前优先级

### 当前阶段

| 方向 | 权重 | 原因 |
| --- | ---: | --- |
| 算法与独立编码 | 50% | 当前最大淘汰风险，已有题量但依赖题解记忆 |
| 后端核心链路 | 25% | 有实践但缺少系统化、可靠性和原理表达 |
| Agent 底层机制 | 20% | 主投岗位差异化能力，需要从使用提升到工程理解 |
| 前端维护 | 5% | 已有相对优势，先维持手感并补关键盲区 |

### 算法达到基础门槛后

调整为：

| 方向 | 权重 |
| --- | ---: |
| 算法与面试手写 | 30% |
| 后端与系统设计 | 25% |
| Agent 项目与原理 | 35% |
| 前端与项目表达 | 10% |

## 6. 学习原则

1. **共享底座优先**：先学能同时提升三个岗位的内容；
2. **面试门槛优先**：先修复会导致提前淘汰的问题；
3. **原理先于框架**：先实现最小闭环，再学习 LangGraph 等框架；
4. **证据驱动**：每个主题必须产出代码、设计、测试或口述记录；
5. **独立完成区**：训练首轮禁止 AI 直接生成答案；
6. **项目复用**：用一个生产化 Agent 项目支撑三个岗位，不重复造三个 Demo；
7. **动态核验**：招聘要求、模型 API、Agent 框架和协议在投递前重新检查。

## 7. 暂不投入的方向

在主线达到求职门槛前，暂不深挖：

- 基础模型预训练和复杂数学推导；
- RLHF、Agentic Model 训练和分布式训练；
- Kubernetes、Service Mesh 和超大规模微服务治理；
- WebGL、浏览器内核和框架完整源码；
- 多智能体复杂协作；
- 为追热点频繁切换框架和语言。

## 8. 最终求职证据

秋招准备最终需要形成四类可验证产物：

1. **算法证据**：混合题识别率、独立实现率、间隔复现记录；
2. **项目证据**：可运行的 Agent 全栈项目、测试、部署和评测；
3. **面试证据**：基础知识问答、系统设计和项目追问材料；
4. **简历证据**：美团实习与个人项目中可量化、可追问、可复述的成果。
