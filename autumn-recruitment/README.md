# 秋招准备知识库

> 创建日期：2026-08-03  
> 目标岗位：AI Agent 开发、全栈开发、前端开发

## 1. 求职定位

当前采用一条共享主干，而不是分别学习三套割裂的知识体系：

```text
软件工程与算法基础
→ 前端交互与工程化
→ 后端业务与可靠性
→ AI Agent 能力与业务集成
```

岗位优先级暂定为：

1. **AI Agent 应用开发**：主投方向；
2. **全栈开发**：能力底座与重要投递方向；
3. **前端开发**：已有相对优势，作为稳定投递方向。

## 2. 当前能力概况

- 前端：相对熟悉，已有项目和工程实践；
- 后端：有全栈实践，但系统性和底层理解仍需补足；
- Agent：了解应用层概念，底层运行机制和生产化能力需要补足；
- 算法与手写代码：当前最大短板；
- 算法主语言：**Python**；
- 已刷题量：约 200 道，主要按灵茶山艾府题单专题训练；
- 当前核心问题：隔一到两周重做中等题时，主要依赖原题解记忆，尚未稳定形成独立推导能力。

## 3. 当前学习策略

现阶段不平均学习三个岗位，而是优先修复淘汰风险：

| 方向 | 初始时间占比 | 阶段目标 |
| --- | ---: | --- |
| 算法与手写代码 | 50% | 能从题目性质独立推导并实现常见算法 |
| 后端开发 | 25% | 能解释和实现完整业务链路与可靠性机制 |
| Agent 底层 | 20% | 脱离大型框架理解并实现最小 Agent Loop |
| 前端维护 | 5% | 保持手感，补齐底层原理和 Agent UI 能力 |

算法稳定后，逐步把时间转移到 Agent 项目、后端系统设计和面试表达。

## 5. 更新原则

后续学习记录遵循以下原则：

- 不以刷题数量作为主要指标；
- 区分模式识别、状态构造、代码实现和边界验证；
- 优先记录可迁移的推导规则，不保存大段标准答案；
- 技术框架和招聘要求等动态信息，在正式投递前依据官方文档和最新岗位重新核验；
- 每个学习主题都必须包含一个脱离 AI 独立完成的验证任务。
