# 简历策略与事实审计

> 目标：先把已有真实经历转化为可信证据，再决定是否继续扩展个人项目。

## 1. 简历版本

### AI 应用全栈版

优先顺序：

1. 美团实习；
2. Agent 全栈项目；
3. 能证明完整交付、异步状态和可靠性的项目；
4. 前端工程能力作为产品交付优势。

技能关键词围绕：Python / TypeScript / Java、Agent Runtime、Tool Calling、RAG、Evaluation、Trace、Spring Boot、SQL、前端 AI 交互。

### 前端版

优先顺序：

1. 美团实习中的前端和全栈贡献；
2. React / Next.js / Vue / TypeScript 项目；
3. 性能、复杂状态、工程化、测试；
4. 流式输出、长任务、引用和工具确认等 AI 原生交互。

不建议维护三份完全独立简历。使用一份事实源，通过顺序、标题、技能和 bullet 选择生成两份版本。

## 2. 美团经历 Week 0 任务

先收集事实，不急着润色：

```text
团队/模块背景：
用户或业务问题：
原有链路：
主要痛点：
我的职责边界：
前端改动：
后端改动：
文件提交与解析如何解耦：
异步状态有哪些：
失败和重试如何处理：
方案为什么这样设计：
评审、测试和上线证据：
可公开的结果：
不能公开的内容：
```

第一版至少形成三条候选 bullet：

- 快速接手陌生系统和建立模块认知；
- 文件提交与解析解耦、异步状态机；
- 一个具体前端或全栈功能及用户价值。

## 3. Bullet 结构

优先使用：

```text
问题 / 约束
→ 我的关键动作
→ 采用的机制或方案
→ 可验证结果
```

一条 bullet 只表达一个主结论。技术名词只用于解释动作，不作为结果。

## 4. 事实审计清单

每条现有和新增 bullet 都要检查：

- 事实是否准确；
- 个人职责和团队职责是否区分；
- 指标是否有基准、环境、样本和测量方式；
- 因果是否成立；
- 是否使用“根本解决、显著提升”等过强结论；
- 是否把安全配置错误描述成另一类安全能力；
- 是否把 AI 生成代码量或文档数量当作业务价值；
- 是否触及保密信息；
- 是否能回答至少三层追问；
- 项目和代码是否与描述一致。

## 5. 当前简历重点攻击面

### 安全因果

“环境变量不暴露在客户端”可以证明密钥管理边界，但不能直接推出“从根本上防范 XSS”。涉及 XSS 时必须说明不可信输出编码、危险 HTML、CSP、Cookie 和运行时边界。

### 性能指标

如首屏 1.2 秒、包体 1.6MB，需要说明：

- 测量工具；
- 网络和设备环境；
- 优化前后基准；
- 是实验数据、线上数据还是本地数据。

无法重现时改成机制性描述，不保留精确指标。

### AI Coding

避免只写：多 Agent、Token 降低、效率提升、文档数量。

改为证明：

- 如何建立需求和验收标准；
- 如何隔离上下文和任务；
- 如何审查 Diff、测试和处理失败；
- AI 协作如何改善了具体交付结果。

## 6. 每条经历的追问树

至少准备：

1. 为什么做；
2. 你具体做了什么；
3. 技术链路；
4. 最难约束；
5. 替代方案；
6. 失败和排查；
7. 数据扩大十倍；
8. 如果重做会改变什么。

回答中不能依赖简历原句或文档提示。

## 7. 完成标准

Week 0：

- 美团事实素材完整；
- 至少三条候选 bullet；
- 两个简历版本骨架；
- 当前简历所有指标和绝对结论完成审计。

投递前：

- 每条核心经历可完成 3 分钟讲解；
- 每条 bullet 有证据和追问答案；
- AI 应用全栈版与前端版均通过一次模拟审查；
- 简历与仓库、演示和实际技术栈一致。
