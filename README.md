# Resume

个人简历版本仓库。用于保存**已确认可发布**的简历版本及其投递产物，并通过版本化方式保留历史记录。

> 当前求职方向：**AI 应用开发工程师 · 全栈开发工程师**

## 当前发布版

- Markdown：[`versions/resume-26-08-1505.md`](versions/resume-26-08-1505.md)
- PDF：`versions/resume-26-08-1505.pdf`
- 发布日期：2026-08-22

`resume.md` 为仓库早期历史版本，保留用于追溯，不作为当前投递版本。

## 仓库结构

```text
Resume/
├── README.md                 # 仓库说明、当前版本指针与管理规则
├── resume.md                 # 早期历史版本，仅保留追溯
└── versions/
    ├── resume-yy-mm-dddd.md  # 发布版 Markdown 内容源
    └── resume-yy-mm-dddd.pdf # 与该版本对应的投递 PDF
```

## 版本命名

发布版本统一使用：

```text
resume-yy-mm-dddd
```

Markdown 与 PDF 必须使用相同版本号，例如：

```text
resume-26-08-1505.md
resume-26-08-1505.pdf
```

版本号用于区分每一次独立发布，**禁止通过覆盖旧文件的方式更新简历**。

## 管理规则

### 1. 草稿与发布严格分离

- 未完成优化、仍在讨论或候选阶段的版本属于 Draft，不进入本仓库。
- 草稿仅在外部工作区维护。
- 只有经过明确确认“可以提交 / 可以发布”的版本，才允许写入 GitHub。
- “生成草稿、润色、讨论、制作预览”均不等同于发布授权。

### 2. 发布版本不可覆盖

- 已发布的 `resume-yy-mm-dddd.*` 视为不可变历史记录。
- 后续即使只修改一个词，也应创建新的版本号。
- 不修改、替换或删除历史发布版，除非明确要求进行仓库清理或纠错。
- README 中的“当前发布版”始终指向最新确认版本。

### 3. Markdown 与 PDF 职责分离

- `.md` 是简历的**内容源**，用于维护文本、结构与版本差异。
- `.pdf` 是正式**投递产物**，用于视觉排版和实际提交。
- PDF 不直接作为内容编辑源；内容调整应先回到 Markdown，再生成新的 PDF 与版本。
- 同一发布版本的 Markdown 与 PDF 内容应保持一致。

### 4. PDF 发布规范

正式 PDF 默认满足：

- 页面尺寸严格为 **A4（210 × 297 mm）**。
- 优先保持单页；不得以过小字号牺牲可读性强行压缩。
- 使用专业、克制的视觉层级和配色，避免影响 ATS / HR 阅读。
- 发布前检查中文字体、链接、分页、裁切、重叠和联系方式。
- “转正实习”等重要标签可在视觉层强调，但不得改变事实含义。

### 5. 内容治理原则

- 以真实、可解释、可在面试中展开的经历为准，不堆砌无法证明的关键词。
- 技能必须尽量能够由实习、项目或其他证据支撑。
- 优先展示 Ownership、工程结果、复杂度和方法论，不以代码行数等低价值指标作为核心成果。
- AI 相关表述重点体现工程能力，例如 SDD、Agent Workflow、Context Engineering、Verification 与 Tool Use，而非单纯罗列模型或工具名称。
- 不提交公司机密、内部链接、敏感数据、账号凭据或未公开业务信息。

## 发布流程

```text
Draft
  ↓
内容审查与精简
  ↓
明确确认发布
  ↓
冻结 Markdown 内容
  ↓
生成并检查 A4 PDF
  ↓
创建新的版本号
  ↓
提交 Markdown + PDF
  ↓
更新 README 当前发布版
```

发布前至少确认：

- [ ] 求职定位与目标岗位一致
- [ ] 联系方式和链接有效
- [ ] 教育、实习、项目时间准确
- [ ] 核心 bullet 能说明“做了什么 / 为什么 / 结果是什么”
- [ ] 技能与经历能够相互印证
- [ ] Markdown 与 PDF 内容一致
- [ ] PDF 为严格 A4，排版无裁切、重叠或字体异常
- [ ] 未包含敏感或不应公开的信息

## Commit 约定

建议使用简洁、可追踪的提交信息：

```text
resume: publish resume-26-08-1505
docs: update resume repository rules
fix: correct resume-xx-xx-xxxx metadata
```

其中发布新版本优先使用 `resume: publish <version>`；README 或治理规则修改使用 `docs:`。

## 当前原则

这个仓库不是“永远只有一份最新简历”的覆盖式存储，而是一个**可追溯的简历发布历史**：

> Draft 留在工作区，Release 才进入 GitHub；历史版本保持不变，README 负责指向当前版本。
