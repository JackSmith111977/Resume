# Resume

个人简历版本仓库，用于保存**已经确认可发布**的简历内容源与正式投递产物，并通过不可覆盖的版本机制保留完整历史。

> 当前求职方向：**AI 应用开发工程师 · 全栈开发工程师**

## 当前发布版

- Markdown：[`versions/resume-26-08-1506.md`](versions/resume-26-08-1506.md)
- PDF：[`versions/resume-26-08-1506.pdf`](versions/resume-26-08-1506.pdf)
- 规格：彩色单页 A4（210 × 297 mm）
- 发布日期：2026-08-22

`resume.md` 为仓库早期历史版本，仅用于追溯，不作为当前投递版本。

## 仓库结构

```text
Resume/
├── README.md                  # 仓库入口、当前版本指针与管理规则
├── resume.md                  # 早期历史版本，仅保留追溯
└── versions/                  # 正式发布版本，不可覆盖
    ├── resume-yy-mm-dddd.md   # Markdown 内容源
    └── resume-yy-mm-dddd.pdf  # 对应正式投递 PDF
```

## 版本命名

正式版本统一使用：

```text
resume-yy-mm-dddd
```

同一发布版本的 Markdown 与 PDF 必须使用相同版本号，例如：

```text
resume-26-08-1506.md
resume-26-08-1506.pdf
```

每次独立发布都创建新版本。**禁止通过覆盖旧文件更新简历。**

## 管理规则

### 1. Draft 与 Release 严格分离

- 未完成优化、仍在讨论、预览或候选阶段的版本属于 Draft，不进入本仓库。
- Draft 仅在外部工作区维护。
- 只有明确确认“可以提交 / 可以发布 / 推送到仓库”的版本，才允许进入 GitHub。
- 草拟、润色、生成 Markdown、制作 PDF 或预览均不视为发布授权。

### 2. 发布版本不可覆盖

- `versions/resume-yy-mm-dddd.*` 一经发布即视为不可变历史记录。
- 后续即使只修改文字、样式或排版，也必须创建新的版本号。
- 不修改、不替换、不删除历史发布版本，除非明确执行事实纠错或仓库清理。
- README 的“当前发布版”始终指向最新明确确认的版本。

### 3. Markdown 与 PDF 职责分离

- `.md` 是**内容源**：维护事实、文字、结构及版本差异。
- `.pdf` 是**正式投递产物**：负责视觉设计、排版和最终提交。
- 内容变更应先更新 Markdown，再重新生成 PDF，并发布为新版本。
- 同一版本 Markdown 与 PDF 的事实内容必须保持一致；视觉布局可以不同。

### 4. PDF 发布规范

正式 PDF 默认满足：

- 页面尺寸严格为 **A4（210 × 297 mm）**。
- 优先单页，但不得通过过小字号牺牲可读性。
- 使用专业、克制的配色与视觉层级，兼顾 ATS 与人工阅读。
- 发布前检查中文字体、链接、分页、裁切、重叠、联系方式及导出尺寸。
- “转正实习”等重要事实可以通过 Badge / 标签强化，但不得改变事实含义。

### 5. 内容治理原则

- 所有内容必须真实、可解释，并能够在面试中展开。
- 技能应尽量由实习、项目或其他证据支撑，避免关键词堆砌。
- 优先展示 Ownership、工程复杂度、技术决策、结果与方法论。
- AI 相关内容优先体现 SDD、Agent Workflow、Context Engineering、Verification、Tool Use 等工程能力，而非只罗列模型或工具名称。
- 不以代码行数、文件数量等低价值规模指标作为主要成果。
- 不提交公司机密、内部链接、敏感业务数据、账号凭据或其他不应公开的信息。

### 6. 仓库内容边界

允许长期保存：

- 已确认发布的 Markdown 简历。
- 与该版本一致的正式 PDF。
- README 与必要的版本治理文档。

默认不保存：

- DOCX、HTML 中间产物。
- PDF 渲染截图。
- 临时脚本、缓存、字体或构建目录。
- 未确认发布的草稿和实验版。

## 发布流程

```text
Draft
  ↓
内容审查与精简
  ↓
明确确认发布
  ↓
冻结 Markdown 内容
  ↓
生成并检查 A4 PDF
  ↓
创建新的版本号
  ↓
提交 Markdown + PDF
  ↓
更新 README 当前发布版
```

发布前至少确认：

- [ ] 求职定位与目标岗位一致
- [ ] 联系方式和外部链接有效
- [ ] 教育、实习、项目及奖项事实准确
- [ ] 核心 Bullet 能清楚表达职责、技术决策与结果
- [ ] 技能与经历能够相互印证
- [ ] Markdown 与 PDF 事实内容一致
- [ ] PDF 为严格 A4 且无裁切、重叠、字体异常
- [ ] 未包含敏感或不应公开的信息
- [ ] 新发布未覆盖任何历史版本


- `resume:`：正式版本发布。
- `docs:`：README / 仓库治理规则调整。
- `fix:`：仅用于明确的事实或元数据纠错。

## 核心原则

这个仓库不是覆盖式的“最新简历文件夹”，而是一个**可追溯的简历 Release 历史**：

> **Draft 留在工作区，Release 才进入 GitHub；历史版本保持不变，README 只负责指向当前正式版。**
